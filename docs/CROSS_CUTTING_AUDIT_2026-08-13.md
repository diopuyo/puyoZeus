事故を3つの型に定義し、3体 (📚台帳監査 / 🔬配線監査 / 🔬暗黙前提監査) で全域掃索した結果。

## 発見サマリ (直すべきもの、優先度順)

### P1: 配線漏れの現存3穴 (型B — 「採用済みなのに効いていない」)
| 穴 | 影響 | 対処 |
|---|---|---|
| **visualize_recognition.py** が本番認識フラグ6種+表示フラグ2種を自動適用しない | レビュー動画が劣化認識で生成される = レビュー体制の信頼性を直撃 | overlay と同じ自動適用パターンを移植 (即修正) |
| **measure_stable_cell_acc.py (物差し)** が同フラグを手渡し前提 | 99.5%基準の測定器が「担当者の注意力に依存した偶然の正しさ」 | 同上 (旧構成の再現オプションは明示的に残す) |
| **collect_indicators_v2.py (旧収集)** が完全欠落 | 主経路からは引退済みで実害限定 | 「本番収集に使用禁止」の明示 or 配線 (user判断) |
- **根本原因**: 認識ライブラリ本体 (load_default) の既定値が採用後も False のまま。
  他の採用フラグは既定値ごと反転させた前例があるのにこの6種だけ据え置き
- **恒久対策**: ①「文字列があるか」でなく「実際に渡された値」を検証するテストへ置換
  ②全エントリポイント起動時に最終構成を1行JSONでログ出力 (describe() は存在するが誰も呼んでいなかった)

### P4: おじゃま収支の1P/2P非対称 (A-3) — 調査が大きく前進
仮説3つを計装で検証:
1. 呼び出し順序バイアス → **反証** (2万件の順序入替テストで完全一致)
2. 配置数の非対称 (2Pの方が手数が多い傾向 29/36動画) → 弱い寄与 (相関0.20、主因ではない)
3. **サンプリング非同期 → 最有力**: 収支は同一瞬間なら厳密に「2P値=−1P値」の対称になるべきところ、
   記録タイミングが側ごとに独立 (自分の盤面が変わった時だけ記録) なため対称性が破壊される。
   共通時間軸に再同期すると全6動画で同方向の残差 (+2.0〜+4.5) = 構造的機序を強く支持
- **【決着 8/13 午後】**: 会計コアは無罪 — 瞬時対称 (net_1p+net_2p=0) は合成9万ティックで
  残差ゼロの厳密成立。真因 = **各側の記録が「自分の設置直後 (=自分のpending消化直後 =
  自分に有利な瞬間)」に構造的に偏る**サンプリングバイアス。対称乱数の合成テストで
  実データと同符号・同水準の残差 (+2.26 vs 実測+2.70、30/30シード同符号) を再現し確定。
  実力差とは無関係 → ドメイン確認は不要になった
- **対処**: 既存148本には「分析時の時刻再同期 (merge_asof)」で無再収集適用 (CSVツールに
  実装、diff列と同じ確立済みパターン)。将来の収集には「側非依存の密な会計記録列」を
  設計採用 (Phase J / 次回再収集から)。**148再学習の前に必須**
