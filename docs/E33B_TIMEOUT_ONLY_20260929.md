# E33b: 段間隔タイムアウトだけの候補除外

## 実装と比較条件

`--prefire-stage-timeout-only` は既定OFF。E32の二フラグと併用すると、段の式を最後に観測してから1.886666667秒を過ぎ、当該フレームに式が見えない場合だけ長い候補を除外する。既存E33の `--prefire-stage-timeout` はそのまま残し、同時指定は拒否する。NEXT・slide・おじゃま終了通知による候補除外は新条件では行わない。全候補消失時の撤回は従来どおり。

段間隔1.17秒、観測余裕0.65秒、式の確認2フレーム/30HzはE33の既存物理定数を維持した。production_config.pyは変更していない。

## 新しい得点誤差の定義

採用瞬間の誤差は後の候補除外で変わらないため合否から外した。E32で採用され実得点が確定した従来の73連鎖を維持し、観測開始から最終終了通知までのS3_provisional/S3_landing表示行を事前固定した。qは36連鎖4,411行、fcは37連鎖6,991行、計11,402行（重複を除く表示時刻10,302行）。両側が対象連鎖中なら連鎖ごとに一件とし、長い連鎖は表示時間に応じて重くなる。

各表示行の予測は、表示に選ばれた評価を作った時点の得点入力。隠し段候補ごとに観測済み得点の下限を適用してから平均する。候補撤回後は従来の暫定得点、表示保持中は元の評価の入力得点を使う。後に得た段や真値で保持中の予測を書き換えない。E33・E33bで撤回された行も同じ母数に残す。真値はE32保存結果の最終実得点で固定した。

原票は `logs/e33b/cohort/*.json`、三条件の表示由来は `score_rows.jsonl.gz`、対応付けた予測・真値は `SCORE_ROWS.npz`。計測フックは評価器を変更せず、E32とE33の保存出力との厳密一致を別途確認する。

## zenchiの原因切り分け

E32で正解・E33で不正解となった151行を結果を見る前に固定した。改善行は0。終了信号だけを残す監査用対照と、タイムアウトだけを残すE33bの2×2比較を行う。終了信号のみで悪化・タイムアウトのみで復元した行を終了信号由来、逆をタイムアウト由来とし、両単独で悪化する行・両機構の組合せでのみ悪化する行も別分類する。

実測は終了信号56行、タイムアウト95行、双方単独0行、相互作用0行。終了信号由来は内部game_idx=5の51行と15の5行、タイムアウト由来は11の95行。終了信号のみの対照は7,608/8,333行、E33bは7,569/8,333行正解であり、終了信号の削除だけでは91.67%へ回復しない。したがって「151行の悪化は終了信号側」という見立ては成立しない。

## 得点誤差の結果

同じ73連鎖・11,402行で、E32 / E33 / E33bの平均絶対誤差は796.001786 / 1,708.838131 / 800.705786点。P95は6,366 / 3,846 / 6,366点、P50はいずれも0点。E33bは平均が4.703999点悪化し、P95は不変なので、両改善を要求した条件を満たさない。E33はP95こそ下がるが平均は大幅に悪化する。初回採用時の誤差とは別の、表示時間で重み付けした結果である。
