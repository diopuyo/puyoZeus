## 1. 対象構成・比較基準・固定する仮定

### 1.1 対象構成【踏襲】

採用候補は B-full の1系統とする。`F_static` と `F_exchange` の2評価器で構成し、撃ち合い内部の S1′/S3′/暫定/仮想着弾 G_fe の切替と平均を廃止する。
時間軸の一往復計算の出力を `F_exchange` に入れる。設計書3.5の状態選択と3.6の独立死亡証明を採用契約とする。欠測・遅延は品質状態として扱い、別の勝率モデルへ逃がさない。

B-data / B-log / B-time、時間群除去、静止K除去は開発集合での機構診断に限る。外側CV・段2・封印の結果を見て、診断構成を採用候補に昇格させない。

**B3 で追加する構成上の確定事項:**
- 局面列は user 定義（§2.5）だけを使う。`fill_phase`・`elapsed_*`・`m0_logit_x_fill_*` を新特徴へ流用しない（照合表 G01）。
- 盤面が `is_dead` のときに K 火力を 0 にする処理（`exchange_event_features.py:90`）は使わない。火力は計算して渡し、窒息は mask 列で別に渡す（DECISIONS 10/5、照合表 G30）。
- CNN の end-to-end 学習は B3 では行わない【確定】。M0 の logit を特徴に使う場合は、M0 を外側 fold ごとに train 側だけで学習し直し、train 行には内側 OOF の値を入れる。既存の固定 M0 は144本（本書の58本を含む）で学習済みのため使わない【確定・設計書6.2】。

### 2.3 fold 割当の生成手順【提案・C3】

外側CVは元動画 group 単位の5fold【踏襲】。全時点・全試合・左右反転・分割を同じ group に置く。
学習 seed は 1003/1004/1005【確定】。fold 割当は seed によらず1つに固定する（seed はモデル学習の乱数だけを変える）。

手順（決定的に生成する）:
1. group キーを作る。単一動画の group は YouTube ID、複数動画の group は構成 YouTube ID を昇順に `+` で連結したもの（例 `iZZyNGtJ3G8+zB8d1FuCStU`）。
2. 各 group の試合数 n_g を数える。完了票の実試合数を使い、欄が無ければ学習行の試合境界から数える。
3. group を `sha256("B3-outer-v1|" + group キー)` の16進文字列の昇順に並べる。
4. その順に1つずつ、その時点で試合数合計が最小の fold に入れる。同点なら fold 番号の小さい方に入れる（fold 0〜4）。
5. 割当表（group キー、所属動画、n_g、fold）を TSV に保存し、その SHA256 を本書に追記してから学習を始める。

内側CVは3fold【踏襲】。外側 fold k の train 側に同じ手順を適用し、塩を `"B3-inner-v1|outer" + k + "|"` に変える。
bootstrap は元動画 group 単位の対応付き再抽出、2,000回、seed 1003、百分位95%区間【確定・踏襲】。

［学習開始前に記入］外側割当表 TSV の SHA256、fold 別の group 数と試合数。

### 2.4 行・教師・重み【踏襲】

行は、設置・段・候補・会計・着弾更新と固定 heartbeat 時点の、実入力 snapshot とする。未来の終点得点・NEXT・起点修正を特徴へ遡及しない。
教師は最終勝敗。保持秒で時間加重し、試合内の重みを1に正規化して、試合等重みで集計する。左右の複製は重みを二分する。

LL は自然対数。数値を安定させるため、全構成共通で p を [1e-6, 1−1e-6] に clip する。Brier は勝敗との二乗誤差、ECE は10等幅 bin。試合等重みのほか動画等重みも副次報告する。
差は候補−比較相手で取る。3 seed の成績は平均してから比較し、独立な動画として水増ししない。
精度の確率 p、表示 EMA 後の p、死亡証明の状態は別々に保存する。LL/Brier/ECE は平滑前の p で採点する。

推論に失敗したときは、同じ試合の最後の p を最大500ms保持し、以後は null にする。null は全提供時間の LL/Brier/ECE で p=0.5 として課点する。保持率・null 率・要求H未達率は分母付きで別に報告する。

### 2.5 層の定義【確定・C6/C7】

すべて当時までに観測された情報だけで決め、将来の情報で層を選ばない【踏襲】。

- **局面**: 各側の「色ぷよ＋おじゃま」の総量（隠し段 row0 を含む）を数え、両側の大きい方（max）を取る。≤18 を序盤、19〜47 を中盤、≥48 を終盤とする。行ごとに計算するため、撃ち合いで序盤へ戻ることがある。本番 G_fe の「両者平均を1/3・2/3で切る」局面は使わない。
- **本線後（層別採点）**: ある側の発火が完走し、その発火の消費率が0.6以上と観測された時点から、次の試合境界までを本線後とする。
  - 消費率 = 消えた色ぷよ数 ÷ 発火時に保持していた色ぷよ数
  - 発火時の保持数は、発火前の確定盤面（row0 含む）の色ぷよ数で数える
  - 消えた数は、主経路が「発火前盤面の色ぷよ数 − 完走後盤面の色ぷよ数」（自連鎖中は操作中ツモが無いので新しい色ぷよは入らない）。副経路は、全段の式が観測できた場合の式消去数の合計とする
  - 主経路が欠測で副経路がある場合は副経路を使う。両方が欠測なら、その発火は「消費量欠測」とする
- **本線判定不能**: 消費量欠測の発火が完走した時点から、次に本線と判定できる発火、または試合境界までを「本線判定不能」層とする（すでに本線後に入っている区間は本線後のまま）。この層は件数・保持秒・LL を報告するが、層の門には使わない。
- **撃ち合い / 静止**: 設計書3.5の2状態【踏襲】。
- **両者構築**: 静止 mode で両側が STABLE【踏襲】。
- **両者CHAIN**【踏襲】。

**特徴として持つ列【確定】:** 本線の判定は学習に任せ、次の両方を別の列で持つ。
- 「60%以上の消費を観測済み」（側別、欠測 mask 付き）
- 「7連鎖以上の完走を観測済み」（側別）

**構成:** 作成時点（58本）で対戦者を辺とした動画のつながりを調べると、最大の連結成分が35本ある。対戦者が互いに重ならない5fold 分割は作れないため、次の方式にする。
- 対象選手 = 3本以上の動画に出ている選手（作成時点で14名: のらすけ8・ともくん8・delta7・ゆうき5・light4・SAKI4・live4・ちゃるめらー4・なしー4・やまだ4・にゃんきち4・いさな3・とりいぬ3・ひまこ3）。学習開始時の最終集合で数え直す。
- 選手 P ごとに「P 除外」モデルを作る。test は P が出ている全動画、train はそれ以外の全動画とする（同一 group の動画も train から除く）。外側CVと同じ設定選択手順・seed 1003 で学習する（計算量を抑えるため副次CVは seed 1003 のみ）。
- **対照（データ量の補正）**: test の動画は同じにする。train からは P と無関係な動画を、P 除外で減った本数だけ無作為に除く（seed 1003、`sha256("B3-player-ctrl|"+P)` 順で先頭から）。こうして、train の本数をそろえた本CV 型のモデルを作る。

**乖離の指標:** 選手ごとに d_P = LL（P 除外）− LL（対照）を、test 動画の試合等重みで求める。全選手を合わせた d̄ は、選手の試合数で重み付けする。動画が重複する選手は、それぞれの選手の中で数える。

**保留条件【提案】:**
- d̄ > +0.02、または
- d_P > +0.05 の選手が1名以上、かつその選手の test が20試合以上

0.02 は元案の層の上端の許容（+0.020）と同じ大きさにした。「個人を見たことがあるだけで、層の門の許容幅を食い尽くす」ほどの差は、汎化として説明できないためである。
保留時は、対戦者を手がかりにした特徴（序盤の形・癖に強く依存する列）を特定して統括へ戻す。報告には R_cv にも同じ手順を適用した d̄（R の構成自体の癖依存）を併記する。

### 5.1 成立条件【確定（user）＋形式化は提案】

時刻 t に受け側 X について、次をすべて満たすときだけ `proven_dead` を返す。

1. **予告の確定**: X に向かう未決済の予告おじゃま N_X ≥ 72。N_X は相殺の処理を済ませた後の値とする。発生源は相手の連鎖で、その連鎖の確定（連鎖側の NEXT 移動、または連鎖側へのおじゃま落下）が観測済みであること。
   - 確定していない進行中連鎖の予測量は含めない。
   - N_X の値は §2.7 で決めた主入力から取る。もう一方の入力と10個以上食い違う場合は `unknown` とする【提案】。
2. **72個の物理的意味**: 着弾は6列へ均等に floor(N/6) 個ずつ配られ、端数がランダムな列へ行く（landing_pattern 7/17）。72個なら全列に12個以上が確定する。12個あれば、空の3列目でも可視最上段（row=1、DEATH_ROW=1）まで埋まる。
3. **打ち返せないことの上界**: X が着弾の完了（3列目の可視最上段が埋まるまで）までに送れる相殺量の楽観的な上界を U_X とする。N_X − U_X ≥ 72 のときだけ成立する。U_X は次をすべて覆うこと。
   - X が置けるすべての手（操作中ツモが未確認なら未知として含める。未知ツモは4色候補集合のすべての組。合法配置のすべて）
   - 1回の着弾は最大30個（5段）なので、72個は複数回に分かれて降る。その間に X が置く手と、その手による発火・相殺を含める
   - 着弾したおじゃまが X の消去に巻き込まれて消えることで、3列目の高さが下がる可能性を含める
   - 手数の上限には中央値版・下位10%版の1手時間を使わない。時間を使う場合は物理的な下限（最速の設置間隔の下限）による上界だけを使う
4. **保留条件**: どちらかが連鎖中なら保留する（death_during_chain 8/22）【踏襲】。打切り・有限 MC・候補の切捨て・一往復より先の未探索は証拠にしない【踏襲・設計書3.6】。確率を0/1に丸めて確定させない。

U_X の計算方法（例: 盤面と今後の全手の色ぷよ数から作る火力上界、または網羅探索）は、実装の着手前に本書へ追記して固定する。小さな盤面での網羅探索との照合テストで、上界が実際の最大値を下回らないことを示す。
［第1版は対象外・合格後の別登録で記入］U_X の算法・照合テストの件数と結果・実装 commit。
