# 画像なし認識の通し比較を旧新の別プロセスで実行する

最終票は fix2 の4動画・676,446連続フレームの比較とする。冷えた区間の対比較は途中起動の補助票に限り、通し比較の代わりには使わない。

`image_free_stream.py` は旧または新を単独で実行し、フレーム別の全観測値、復号画像SHA、PTSを保存する。新は0から通し、旧は検証済みの前史CPからの後半と、0から計算する前方補完を使用できる。新へfix1のCPを流用しない。`death_0` / `death_1` を含む既存の観測項目は維持する。

`image_free_stream_merge.py` は旧CP接続部の重複検算8フレームを全項目照合してから所有分を連結する。各動画で旧新とも0から最終まで欠落・重複0を要求し、既存の比較関数を動画順に呼び出して場面数を集計する。処理完了を品質合格へ読み替えない。

2026-10-08の検証票はリポジトリ外 `b3_data/codex_tasks/image_free_speed_stream_v1/route_proof.json`。c68 f11800–12159の旧新単独各360fと、f11980からの旧新CP再開各180f、計1,080経路フレームが同居版の全項目・画素SHA・PTSと一致した。特徴行は34/34/15/15行。受領票には固定ソース一覧・モデルSHA・CP SHAを保持する。

旧キャッシュはコード・モデル・動画SHAで識別し、各チャンク先頭8fを実計算して照合する。本番資産は両台ともリンクを展開した実体ファイルに固定する。`Path.rglob` がディレクトリリンク内を列挙しないため、リンクのままモデルSHAを作らない。固定前後のリンク先を含む全モデル・設定・対象dataの一致票は `materialized_assets_receipt.json` と `delivery_assets_receipt.json`。

並列上限はPC1/PC2各4、合計8。前方補完を含む12作業を順次流す。初回ワーカーのRSSを実測し、Windows/WSLの空き6GiBとCPU負荷から自動調整する。低メモリ時は確定点から再開できるよう自分のワーカーを減らす。PuyoLive監督を維持し、保険 `image_free_fix1_full` の制御ファイルは変更しない。

時間内訳は復号・認識・会計・特徴・推論・監査・保存の排他的計測。初期化は処理秒数に含まない。旧キャッシュ内部の保存などは残余時間となる。初版ではOCR/UI監査の再計算を省略しない。10/8追加検証後の旧経路だけの部分再利用は [監査更新票](IMAGE_FREE_SPEED_AUDIT.md) を参照。速度は旧新それぞれの経路フレームを単位とし、動画ペアfpsと混同しない。

10/8の追加指示により、r2を待たずfix2 78e33b5eで先行起動する。入口は `image_free_revision_supervisor.py`。明示的な先行起動票・固定ソース・モデル・入力・計画・段3票を照合する。検証済み本体は変更せず、監督は配布先の `controls/` に分離する。r2終了コードを0と偽装しない。

`image_free_revision_sync.py` は共有のr2確定票を受信する。ソース・モデルが同じなら旧新とも継続、変わった場合は別世代の全ソース・モデルをSHA照合し、新だけを0から別出力へ取り直す。同じ監督の4枠を共有し、旧プロセス・CP・出力は維持する。通信・検証エラーでも旧を停止しない。最終突合は監督票のroutesが選んだ出力だけを使用する。資産・画像・動画はgitへ追加せず、既定OFFは維持する。

PC2一式は `image_free_speed_stream_pc2_v1`。PC2自身でも同じ1,080経路フレームを再検証してから本番へ進む。B2記録と研究測定の並列を絞って比較を優先する。PC2の開始指示と保険ジョブの切替は統括が担当する。最終tarの場所・SHA、起動状態、条件付き時間範囲は外部の `image_free_speed.SUMMARY.md`（8行）を正とする。
