# E15: 撃ち合い中のcount特徴更新

`--exchange-event-live-count` は既定OFF。`src/production_config.py` は変更しない。
E3親CLIのONでは `models/exchange_event_v3` を選択する。
記録再生器と動画生成器には同じフラグを追加し、モデルの明示指定も引き続き使用できる。

各側のSTABLE確定盤面とNEXTが変わるとcount入力を交換し、S3暫定の評価キャッシュを失効させる。
連鎖進行中は発火時の完走予測盤面を使い、終了後のSTABLEから実測盤面へ戻る。
初回の発火フラグを新盤面へ再適用しない。得点換算は区間発火時、探索火力は評価時刻の換算率を使う。
探索キャッシュは盤面・NEXT・換算率・探索設定をキーとし、同一換算率内の秒数差で再探索しない。
既存のD・到着特徴はそのまま保持する。

学習は `scripts/train_exchange_event_models_v3_20260928.py`。
148原票をティア確認して走査し、各側の無タグSTABLE更新時刻ごとに1行を作る。
同時刻の両側更新は1行にまとめる。評価時刻の充填率で中盤を採否し、未来の区間終点は採否に使わない。
既存のDは同試合の発火前に取得済みの行だけを参照し、得点は観測済み連鎖の分だけを合算する。
終点得点を発火時完走予測の代理とする慣行は維持し、次の同側発火より前の得点で区切る。
原票には終了時刻・state列がないため、タグの観測から次の無タグSTABLEまでを連鎖中として扱う。
初期盤面・過去D・勝敗ラベルのない行は復元しない。採用動画数と原票数は別に記録する。

学習重みは撃ち合い単位で合計1。動画分割はv2と同じ3seed×5fold。
AUC・log lossはv2と同じ行単位で集計し、重み付きAUCも補助値として保存する。
事前登録は `logs/e15/PROTOCOL.json`、全判定は `logs/e15/METRICS.json`。
標準・軽量のいずれかのAUCが0.722を超えたらリーク疑いとして停止し、v3モデルの保存と後続評価を行わない。
閾値を緩めたり合格扱いへ変更したりしない。
