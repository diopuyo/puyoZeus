# OBS 試験手順（2026-10-11・B3＋表示遅れ対策）

自分のPCで試すための版です。テンプレート画像を同梱しています。
配布フォルダは `D:\puyo_analyzer\packaging\build_20261011\PuyoLive`。
10/7の旧版 `D:\puyo_analyzer\packaging\build\PuyoLive` は残してあります。

## 1. ゲーム映像を用意する

起動順は **OBS 起動 → 仮想カメラ開始 → PuyoLive 起動 → OBS のブラウザソースを再読み込み（または起動後に追加）**。

1. 旧版のPuyoLiveが動いていたら、その起動ウィンドウで `Ctrl+C` を押して終了する。
2. OBSを起動し、設定→映像→出力解像度を1920×1080にする（720pでの認識精度は未測定）。
   ゲーム映像を1920×1080いっぱいに配置する。盤面や得点が隠れないようにする。
3. OBSの仮想カメラの出力を「ゲーム映像だけのシーン」に指定して開始する。
   判定表示を仮想カメラへ戻さないよう、判定表示を載せる配信用シーンとは分ける。

## 2. 新版を起動する

1. 上記の新しい配布フォルダを開く。
2. `puyo_live.json` は設定済み。入力が違うときだけ `device_index` を変更する。
   入力番号は、このフォルダでPowerShellを開いて次を実行すると調べられる。

   ```powershell
   .\python\python.exe -m src.phase_j.launcher --list-devices
   ```

   `device_name` は較正用の名前で、入力の選択は `device_index` で行う。
3. `PuyoLive.bat` をダブルクリックする。「入力確認中」「画面調整中 N%」の完了を待ち、対戦を入力する。
   「試合待ち」が続く場合は入力番号の誤りも疑い、`device_index` と仮想カメラの映像を確認する。
4. OBSの配信用シーンにブラウザソースを追加する。
   URLは `http://127.0.0.1:8765/`、幅1920、高さ1080。
   既存のブラウザソースを使う場合は、PuyoLive起動後に再読み込み（キャッシュを更新）する。
5. `output\b3_config.json` が作られ、次が入っていることを確認する。
   - `model_sha256`: `6113e42b8d3aadad6251f0749ad09281d7c63a65fc09a4cc659e68694ee2903c`
   - `search.version`: `b3_pair_potential_v2`
   - `completion_driven`: `true`（評価が完了したら表示へ渡す）
   - `fast_ema`: `true`（表示の追従を速くする）

   B3と表示遅れ対策は設定済み。本番の採用フラグは同梱の
   `app\src\production_config.py` から読み込まれる。

## 3. 数試合を録画して確認する

1. OBSでゲームと判定表示を一緒に録画する。可能なら60fpsにする。
   保存先は `D:\puyo_analyzer\local_frames\obs_test_20261011` とする。
2. 設置、発火、連鎖、着弾、全消し、勝敗確定、次試合で表示を確認する。
   B3の判定が出ること、長く止まらないこと、次試合に前試合の判定が残らないことを見る。
3. 数秒だけゲーム以外の画面へ切り替えて戻す。入力が確認できない状態の表示と、復帰後の判定再開を見る。
4. 遅延は録画をコマ送りし、同じ場面について次の2点の間を数える。
   A＝映像で発火・着弾・勝敗が初めて見えるコマ、B＝対応する判定表示が初めて変わるコマ。
   `遅れ(ms)＝コマ数÷録画fps×1000`。60fpsなら1コマ約16.7ms。
   発火・着弾・勝敗をそれぞれ数例測り、録画時刻・コマ数・fps・遅れをメモする。
   判定が変わらない場面は「変化なし」と記録する。
   この測定は画面から表示までの体感の遅れで、内部の計算時間だけを測るものではない。

## 4. 止めて記録を残す

1. 起動ウィンドウで `Ctrl+C` を押し、終了してからOBSの仮想カメラを停止する。
2. 配布フォルダの `output\` が今回の記録先。再試験前にフォルダ名を
   `output_1回目` などへ変更して残すと、次回は新しい `output\` が作られる。
3. `puyo_live.json`、出力フォルダ、録画、症状の出た録画時刻を保存する。
   特に `b3_config.json`、`b3_updates.jsonl`、`b3_state_timing.jsonl`、
   `metrics.json` と起動ウィンドウのエラーを残す。
   試験開始・終了時刻、入力番号、OBSのfpsもメモする。
4. 終了しない場合だけ、今回起動した親PIDを確認して
   `taskkill /PID <PID> /T /F` を実行する。他のPython作業は止めない。

## 5. 問題が出たら戻す

1. 新版を上の方法で終了する。記録を残す。
2. `D:\puyo_analyzer\packaging\build\PuyoLive\PuyoLive.bat` を起動する。
   OBSのURLは同じなので、そのまま使える。新旧を同時に起動しない。
3. 表示遅れ対策だけを切り分ける場合は、新版を終了した状態で
   `puyo_live.json` に `"display_completion_driven": false` と
   `"display_fast_ema": false` を追加し、再起動する。
   元に戻すにはこの2項目を削除する。モデルや `production_config.py` は編集しない。
