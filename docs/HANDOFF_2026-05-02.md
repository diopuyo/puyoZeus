## 主な発見

### 1. subprocess env propagation バグ (修正済)

`scripts/phase_z_*.py` の 5 ファイルで `subprocess.run(env={"PYTHONPATH": "."})` と env を完全上書きしていたため、`PHASE_Z_*` 環境変数が子プロセスに伝わらず全 sweep 試行が default 動作。

**修正**: `env = {**os.environ, "PYTHONPATH": ".", "PATH": "/usr/bin:/bin"}` に統一 (5 scripts: `phase_z_cross_video.py` / `phase_z_extract_all_violations.py` / `phase_z_night_finalize.py` / `phase_z_run_combined_eval.py` / `phase_z_weak_video_review.py`)。

**確証実験**: `PHASE_Z_EM_S_MIN=200` で v01 hard が 84→576 と劇的変化 = env が完全に伝わるようになった。

### 3. v13 暴走 (調査済、修正不可)

新コード (Z-3A/3B/3C/3D) で v13 のみ -4.565pt 悪化 (98.463→93.898)。原因:
- ChainPhaseDetector の `is_chain=True` frame が +1368 cell 増 (30 秒の 58% が連鎖中扱い)
- `_force_em_airborne` の cascade で多 cell EM 化
- empty_in_stack violation が 67→204 件に急増

修正試行 (3 件):
1. `PUYO_DIFF_FIRE 4→6` + `CHAIN_HOLD_SEC 3.0→1.8` + `diff_fired` に `_has_erasable` 必須化
2. `_force_em_airborne` snapshot 化 (cascade 切断)
3. `_apply_bg_em` に `is_chain` スキップ追加

**結果**: 全て v13 で逆効果 (89.512% / 93.716%)、revert。  
**結論**: cascade は皮肉にも CNN 誤検出を「hide」することで violation 数を減らしていた。v13 改善は **CNN model レベル**でないと不可能。
