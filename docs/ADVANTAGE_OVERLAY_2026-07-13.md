# 有利不利オーバーレイ 試作 + 精度改善 (2026-07-13)

tier1 指標を使い、1 試合を通した**有利不利(勝率)を動画・グラフ・1手診断**で
可視化する試作と、そこで見つかった誤判定の原因究明・改善を記録する。

## 1. 成果物 (scripts)

- `visualize_advantage_overlay.py`: 有利不利オーバーレイ動画。上部バー + 勝率 + 主因、
  下部にリアルタイム評価値グラフ(将棋風)。tier1 軽量モデル(安価指標の差分)で採点。
- `plot_advantage_timeline.py`: 試合全体の有利不利推移(将棋の評価値グラフ風 PNG)。
- `plot_move_diagnostics.py`: 1P 手数ごとの断面 + 有利不利 + 各指標の値/モデル寄与/説明。
- `proto_*.py`: 検証用(tier2火力/潜在火力/exchange/圧力)。

## 2. 見つかった誤判定と原因(v29 game B で調査)

ユーザー目視で「終盤、返し切れない攻撃が通ったのに有利不利が逆」と判明。深掘り結果:

1. **静止スナップショットの限界**: tier1 は「装填して勝つ寸前」と「装填して死ぬ寸前」、
   および「発火して勝った直後の空盤面」を区別できず、発火の前後で有利不利が誤反転する。
2. **火力の静止指標では直らない**: `potential_fire_power`(潜在火力=盤面に仕込まれた
   最大連鎖、ツモ非依存)を実装したが、終盤も「1P 火力圧倒」と出て誤判定は不変。
   **「大連鎖を持つ ≠ 勝ち」**(装填した弾の大きさであって着弾ではない)。
3. **評価側のサンプリングがお邪魔会計を破壊していた(真因の一つ)**: 0.5s 毎更新だと
   会計がスコア変化・連鎖終了を取りこぼし net/forecast=0。**毎フレーム更新で復活**。
4. **モデルが exchange 信号を軽視**: net収支 +33(1P着弾)でもモデルは 2P 有利を出す
   (発火後の密度崩壊が上書き)。

## 3. 改善: 持続「圧力」信号 + ブレンド

- **圧力信号** (`PressureTracker`): board_ojama(直接認識で信頼・win 最強因子 終盤 −0.21)の
  増加を減衰累積(半減期 ~1.5s)した 1P 視点のダメージ差。滑らかで、着弾の記憶を持つ。
- **有利不利 = 0.6×圧力 + 0.4×現モデル**: 攻撃が通った瞬間は圧力(±100)が支配して正しく、
  build 中は現モデルが位置取りを補う。
- 結果: game B 終盤 t=272-273 の決着(2P が 816 お邪魔で 1P の 494 を上回り埋め切り)を
  正しく「2P 圧勝」と表示。以前の「1P 有利」誤反転が消滅、乱高下も大幅減。

## 4. お邪魔会計は健全だった(精度診断の結論)

finalize/offset ログ検証で、会計ロジックは概ね正確と確認:
- t=272.6 1P chain=34586→494個、t=273.2 2P chain=57100→816個(186相殺+630を1Pへ)。
  **2P が上回る連鎖で返して 1P 埋め切り = 2P 勝ち**を正しく計上(ユーザー観察と一致)。
- 「forecast 494 暴走」は本物のゲーム終わらせ連鎖(34586/70≈494)。cap 216 は致死超で無害。
- 「予告 33 なのに盤面 1」は 予告=保留予測 vs 盤面=着弾実測 で設計上のずれ、バグではない。
- 実際に壊れていたのは評価側サンプリング(§2-3、修正済)で会計ロジックではなかった。

## 6. 2026-07-14 自律セッション 改善(火力モデル品質向上)

ユーザー観察「SAKIが撃った(足りず)のに有利不利がSAKI寄り、あんは6万点で勝ったのに」を
深掘りし、火力の扱いを改善。**4成分ブレンド**へ:

```
有利不利 = 0.35×圧力(着弾) + 0.30×得点リード(累積攻撃) + 0.20×現モデル(位置) + 0.15×threat(到達火力)
```

- **真因(Phase1 trace)**: v29 gameB t=50(あん816発火直前)で `reach_fire_power` は
  あん956/SAKI14 と正確だが `potential_fire_power` は あん360 と過小評価。旧threatは過小な
  potentialを使いあんの決定連鎖を見逃していた。さらに発火(scoreが t=53-60で12894→60774)
  →お邪魔着弾(t=70)に **~10秒ラグ**があり、その間は静止指標で捉えられない。
- **M1**: threat を `potential`→`reach_fire_power`(実際に撃てる火力)へ置換。
- **M2**: 「得点リード」信号を追加(各side現在スコア差=どちらが多く攻撃を通したか)。
  当初velocity(発火実行中)版は2番目に撃つ小連鎖側(SAKI 494)を誤優勢化 → 累積リード
  (既により多く撃った=あん)へ変更。着弾ラグを埋める。
- **potential<reach はバグでなく設計差**(potential=理想2個追加=浅い / reach=実ペア2手=
  4個配置=深い)。有利不利には reach を採用。potential は tier2 指標として存置。
- **検証**: gameB → t=38以降ずっと2P一貫・決着-85(2P圧勝)、旧版の誤1P surge消滅。
  gameA(別ゲーム, あん勝ち)→ 決着で強い2P・最後まで2P = 汎化確認(過学習でない)。
- 回帰テスト: `tests/test_advantage_components.py`(圧力/得点リードの符号・減衰・クランプ)。
