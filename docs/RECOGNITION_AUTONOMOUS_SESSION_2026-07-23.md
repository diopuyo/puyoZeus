## 1. 根本原因(残像バグ)

あなたの指摘通り、基幹の認識が連鎖後の盤面を即反映できていなかった。原因は **機能追加同士の整合漏れ(回帰)**:

- 2026-06-06 に追加した **GRAVITY_SETTLE 状態(不具合A修正・PR#13)** が、それ以前からあった **連鎖後盤面確定ロジック(Phase C-6 の C)を構造的にバイパス**していた。
- 現在の既定設定では、連鎖(CHAIN)は必ず GRAVITY_SETTLE を経由して STABLE に戻るため、`prev_state == CHAIN` を条件にした「連鎖後に最終盤面を即反映するコード」が **完全に dead code**(一度も実行されない)になっていた。
- **実データで実証**: c62 game9 の連鎖区間で CHAIN→GRAVITY_SETTLE 34回 / GRAVITY_SETTLE→STABLE 12回 / **CHAIN→STABLE 直行 0回**。
- 結果、GRAVITY_SETTLE→STABLE は汎用の差分マージ経路を通り、CNN が演出残光で「消えたセル」をまだ色ありと誤読していると、**連鎖前の色がそのまま焼き付く=残像**。

## 2. 修正内容と効果

### 修正(セーブポイント `4c2cb11` → タグ `savepoint/recognition-afterimage-fixed` 8c95111)
- ChainEvent を退避保持する新フィールド + 6箇所の連鎖終了処理直前で退避。
- 連鎖後盤面確定と凍結の条件を `prev_state in (CHAIN, GRAVITY_SETTLE)` に拡張し、GRAVITY_SETTLE 経由でも最終盤面(ChainSimulator の結果)を即反映。
- 副次バグも発見・修正(T2 誤色棄却ガードが修正直後の正しい盤面を古い盤面へ即 revert する相互作用)。
- **後方互換完全維持**: `enable_gravity_settle_state=False` 時は 1bit も挙動が変わらない。**全2927テストパス**、新規8テスト。
