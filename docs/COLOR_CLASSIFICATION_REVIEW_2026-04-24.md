# CNN 色分類レビューガイド

**出力時刻:** 2026-04-24 16:26 JST
**目的:** CNN が各セルをどう色分類しているかを、人の目でセル単位で検証する
**対応ツール:** `scripts/verify_color_classification.py` (本レポート生成時に新規追加)
**生成物:** `data/verify/color_review_<frame_stem>.png` (サンプル 8 フレーム分)

---

## 0. 検証のしくみ

```
1920×1080 フレーム
        │
        ▼ (BoardRegion.cell_sample_rect)
  各セル中央の矩形を切り出し (156 パッチ / frame = 6列×13行×1P/2P)
        │
        ▼ (GatedCnnClassifier.classify)
  1) 空/非空ゲート (PuyoPresenceGate)
  2) 非空なら CNN で 7 クラス分類
        │
        ▼ (verify_color_classification.py)
  パッチ画像＋予測ラベルを並べたグリッド PNG を出力
```

**CNN の 7 クラス**: `空(EMPTY) / 赤(RED) / 青(BLUE) / 緑(GREEN) / 黄(YELLOW) / 紫(PURPLE) / お邪魔(OJAMA)` — `src/board.py` の色定数と 1 対 1 対応。

```bash
./venv/bin/python scripts/verify_color_classification.py path/to/frame.png
```

### 出力画像の読み方

- **左 6 列 = 1P 側**、右 6 列 = 2P 側（間に黒い帯）
- 上端にヘッダ `1P` / `2P`
- 各セル = `上 48×48 px: 抽出パッチ画像` + `下 16 px: 予測ラベル色帯＋文字`
  - 文字は `空 / 赤 / 青 / 緑 / 黄 / 紫 / お`（1文字）
  - 色帯は予測クラス対応色（赤予測なら赤帯、紫予測なら紫帯、等）
- 行番号 0=最上段（隠し段 含む）、12=最下段

### 端末に出るサマリ

```
=== frame_0300s.png ===
  1P: 空=34 赤=0 青=13 緑=16 黄=12 紫=1 お=2
  2P: 空=67 赤=6 青=2 緑=1 黄=1 紫=1 お=0
```

各クラスのカウントが 78 (= 6×13) の合計になるはず。合計が 78 でない → バグ。

## 2. 人の目レビュー手順（推奨）

### Step 1: 予測の全体分布を確認

- **空クラスが極端に多い (60+)**: 序盤の空盤面。正常
- **空クラスが極端に少ない (<5)**: 盤面満杯。死の可能性、または全セル何らかの色だと誤認している
- **特定色が 0**: 盤面に本当にその色が無いか、CNN が拾えていないか要目視
- **お邪魔がある**: 相殺前 or 打たれた直後の盤面。数と位置を目視

### Step 2: 画像の各セルを目視でチェック

各セルについて:
1. **パッチ画像（上 48×48）の実物の色を目で判定**
2. **ラベル帯（下）の予測色・文字が目視と一致するか**
3. **不一致セルはメモ**（どの色 → どの色に誤分類したか）

優先的にチェックすべきセル:
- **色帯と実物の色が明らかに違う**セル
- **「空」予測なのにパッチに何か見える**セル（暗所紫→空誤認の典型）
- **「お邪魔」予測なのに実物が色ぷよ**（逆もしかり）

### Step 3: 誤分類パターンを分類

以下の既知の難所と照合:

| 誤分類パターン | 原因 | 対策 |
|---|---|---|
| **暗所紫 → 空** | 1P/2P 側の背景差で暗く見える紫が空セルと誤認 | 暗所紫拡張 5-10× 投入済（本セッションの主要対策） |
| **紫 → 赤** | 紫の彩度低下時に赤判定 | Phase 1 ハード例学習で補正中 |
| **青 → 紫** | 暗い青が紫と混同 | 同上 |
| **黄 → 赤** | 特定フレームで黄の色相が赤寄りに | 調査中 |
| **緑 → 黄** | 連鎖中発光フレームで色が飛ぶ | 連鎖中フレームは学習から除外推奨 |
| **お邪魔 → 空** | 灰色の透過表示で背景に同化 | 低優先 |
| **空 → お邪魔/黄** | 背景グラデーション（特に上段）で誤判定 | 本セッション Phase 1 で "誤認 空→お邪魔: 数百件" として検出中 |

### Step 4: 誤分類が多い場合の切り分け

A. **1 つのフレームで全体的に誤分類 → キャリブレーション問題**
   - `BoardRegion` の `x, y, width, height` が動画の盤面位置とズレている
   - `models/calibration_video01.json` 内容を確認、実フレームに当てて確認
   
B. **特定の色だけ誤分類 → CNN 学習の偏り**
   - その色のハード例が不足 or 過剰
   - `data/training/parallel/` の該当色分布を確認
   - `scripts/long_improve_v2.py` のハード例追加ログを見る（`[注目] <色>→<色> 誤認: X件`）

C. **特定の side (1P or 2P) だけ誤分類 → 背景差**
   - 本セッションで発見された **1P/2P 非対称性**（暗所紫問題）
   - B-1 ストラタ分割実装済（未統合）で対策予定

## 4. 誤分類を見つけた時のアクション

### A. 数個程度の誤分類
- 「このセル」の色を CNN が苦手としているだけなら、次の学習サイクルで Phase 1 のハード例として自動選択される可能性が高い
- 本セッション 40h 学習中なら、milestones.jsonl の `phase1` log で該当色のハード例数が増えているか確認

### B. 特定色が系統的に誤分類
- 該当色の学習パッチが不足している可能性
- `data/training/parallel/` 内の npz をサンプリングして目視チェック
- `scripts/validate_indicators_live.py` の結果と突き合わせ、指標値への波及確認

### C. CNN 側の問題ではなく、キャリブレーション（盤面位置）の問題
- `models/calibration_video01.json` の p1_region / p2_region が現在の動画フォーマットと合っているか
- `data/frames/sample/grid_overlay.png` や `field_detection.png` など既存の可視化を参照

### D. エッジケース（連鎖中の発光フレーム、ぷよ消去中の粒子エフェクトなど）
- そもそも学習から除外する frame（`data/training/parallel/` 側の抽出段でフィルタ）が正解
- `patch_extraction.py` の `ExtractionStats` でフィルタ件数を確認

## 5. 参考: 色分類経路の詳細

### GatedCnnClassifier (`src/patch_classifier.py:257`)

1 段階目: **PuyoPresenceGate** が HSV + 彩度で「ぷよが存在するか」の 2 値判定
  - True → CNN に進む
  - False → `COLOR_EMPTY` を即返す

2 段階目: **CnnPatchClassifier**（44×44 RGB → 7 クラス softmax）
  - Phase 2 で採用された residual(24ch + ResBlock) アーキ
  - argmax でクラス決定（本ツールは argmax のみ使用、確信度は将来拡張余地）

### 既知の長短

**長所**
- ゲートで空セルを高速に除外、CNN 推論コストを減らす
- CNN は各色の特徴に集中できる

**短所**
- ゲートが暗所紫を「空」として早期 reject → CNN に回らない → 暗所紫→空誤認の根本原因
- 本セッションの暗所紫拡張は **CNN 側でハード例として学習** する対策だが、**ゲート側の閾値調整** は未実装（優先度検討中）

## 6. このツールの限界と拡張余地

### 現状の限界
- **argmax のみ表示**（確信度ヒートマップ無し）
- 連鎖中フレームでも無差別に分類する（「このフレームは評価対象外」マークができない）
- パッチサイズ 48×48 表示は粗い（実際の抽出は 44×44 だが、表示上は拡大）

### 次のステップ候補
- 確信度付き表示（top-2 クラスと差分を色の濃淡で）
- クリック/ホバーで正解ラベルを手動入力、誤分類 CSV を吐く
- 1P/2P 側メタ (B-1 strata) 実装後、side 別の誤分類率集計
- 連鎖発光フレーム検出と除外（motion 量で判定）
