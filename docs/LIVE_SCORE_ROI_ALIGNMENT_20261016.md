## 実装と検証条件

- 各側の最初の有効な式12コマ、5Hz、±6px・1px刻み。平均NCC最大、
  1e-6以内の同点は移動量最小、次に横移動最小。合格線0.70を維持。
- 有効式のレイアウト検証も必要。証拠不足の側は現行枠のまま「合わせ中」。
  両側独立に確定し、試合リセットでは保持。追加の公開待ちは設けない。
- 小さな×領域のNCCマップ一枚から169候補を取得。元の個別照合との誤差1e-6以内・
  選択値一致を試験。画像は保持せず候補の合計値だけを保持し、確定後は探索しない。
- 同一コマの得点・式の共有セルを作る前に枠を反映。個数入力用の独立OCRにも同じ
  枠を配送し、既存キャッシュも側・枠・画素をキーにする。B3の入力より後段は変更なし。
- `display.score_roi_alignment` からパネルに「式の枠: 1P 合わせ中 / 2P 0,-2px」を表示。
- 映像比較は `RecognitionPipeline.update` と実際の `ObservationCapture.update` を
  30Hzで180秒、OFF/ON各5,400コマ。row1ガードは両方ON、601→709色補正も同条件。
  個数入力は既存の式段累積器の `formula_step.erased` まで検査する。

再現スクリプトは `scripts/survey_score_roi.py` と `scripts/measure_live_score_roi.py`。
後者は `--video PATH --start SEC --duration 180 --asset-root ASSETS --output JSON`。
計測ログ・集計JSONは作業ツリーの `logs/score_roi_align/` に保存。
長時間処理はWSLの `setsid -f` で実行。新規取得した29・43の動画区間は検証後に削除。
共有されているv39fixの保持済み元動画は保持した。

## 実映像の結果

video_39（258.433秒から180秒、row1ガードON）は、両側とも **(0,-2)px** に確定。
両側確定は起動31.6秒後。較正待ちを含む全10,800側コマで、式の有効読取は
**63 → 1,884（0.58% → 17.44%）**、最大NCCは **0.7089 → 0.9719**。
配信認識内の式キャッシュと個数入力側の読取件数も一致した。
個数入力の確定式段は **3 → 68段**、その `erased` 合計は **12 → 323個**。
これは式で観測できた個数の回復であり、全消去数の正解ラベルとの精度測定ではない。

video_29の無加工映像（199秒から180秒、row1ガードON）は認識結果が **5,400/5,400一致**。
式の有効読取は両方 **1,697/10,800（15.71%）**、確定式段 **62段**、`erased` **338個**。
ただし両側の最適値は **(0,-1)px** であり、NCCを含む生原票は4,473コマで異なる。
自然映像のずれ0は今回の標本では見つからず、無加工映像による「ずれ0で全出力一致」は未検証。
その条件は、同じvideo_29の得点帯だけを1px下へ揃えた実映像対照で別途検査した。
`--score-band-dy 1 --duration 120` の対照は両側 **(0,0)px** に確定し、
認識結果・NCCを含む入力原票が **3,600/3,600コマ完全一致**。
両方とも有効式1,035側コマ、確定38段・217個。単体試験でもずれ0の全OCR返り値一致を確認。

自動合わせ自体の追加時間（video_39、30Hzの全呼出しを計時）は、較正中949コマで
**平均0.211ms、p95 1.452ms、最大2.976ms**。確定後4,451コマは **平均0.00186ms**。
認識＋個数原票取得の全体平均は OFF 32.01ms / ON 31.83ms（実行順交互、初回初期化込み）。
測定機は i7-13620H／WSL、BLAS・torch各1スレッド。低スペック実機の測定ではないが、
追加のモデル推論・全画面探索を使わず、確定後の探索負荷をなくす設計。

単体・関連試験は初回387件通過、追加配線／公開DTOの試験は63件通過（新規32ケースを含む）。
ブラウザ試験ファイルはPlaywright未導入のため1件スキップ。パネルはNodeで7検査通過。
追加Pythonは構文・戻り値型注釈・1関数50行以内を検査。`git diff --check` も通過。
