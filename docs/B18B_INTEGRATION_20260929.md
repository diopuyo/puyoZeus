# B18b：通知単位の表示更新と発火前観測

基点は B18a `e3915d3`。`src/production_config.py` は変更しない。

## 実装

- `NotificationExchangeOverlay` は本番の `ExchangeEventOverlay.update` と
  オフライン再生と同じ `_ExchangeDisplayEMA` を毎通知で実行する。
  公開時の `calculate` は再評価せず、配信は既に求めた最新表示値を読む。
  死亡確定・勝率欠測時のEMA非更新も本番の関数に従う。
- 評価子プロセスも同じクラスを使う。試合journalの再実行には前試合末尾の
  EMAを渡し、再起動によって平滑の初期値が変わることを防ぐ。
- `ImageReader` の既存CNN融合結果を浮遊除去前で複製する。隠し段は既存の
  UNKNOWN処理を適用し、確定盤面と認識器の戻り値は変更しない。
  既存のHSV単独読取も再利用し、未取得かつ品質・着地条件を満たす画像だけ
  HSV単独で追加読取する。追加CNN推論、動画の逆シークは行わない。
- 認識側の `LiveSnapshotInputs` が30Hz・最大72枚の盤面を保持する。
  取得窓36枚（1.2秒）に同じ長さの通知遅れの余裕を加え、過去の発火時刻を持つ
  通知でも窓の先頭を失わない。多数決の対象は常に発火直前の1.2秒だけである。
  E31の `vote_window` を共用し、発火時刻からの取得窓、最初の画像の品質判定、
  多数決、消去・浮遊・エフェクト除外を適用する。欠落フレームは連続区間を分断する。
  同じ発火の再通知には確定した窓を返す。試合・入力切替・較正完了時に窓を破棄する。
  機器の取得時刻の揺れは30Hz区画の半幅未満で対応し、窓外・未来の画像は除外する。
- `prefire_snapshot`、重力待ちの `midchain_board`、死亡確認を認識通知へ載せる。
  E32の履歴分布には、既存のSTABLE確定盤面・状態・NEXT/DNEXTと途中盤面、
  スナップショットの終了時刻を渡す。差分通知を復号した後に評価する。

公開表示1,495/1,694行。reviewは勝率・EMA 6,848/6,848行、公開397/397行で一致。
切り分け再生は `scripts.verify_live_b18b --source zenchi --record <動画通知原票>`
に `--out logs/live_b18b/schema/zenchi --legacy-event-schema` を指定する。
