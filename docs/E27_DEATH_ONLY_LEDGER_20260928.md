# E27: 死亡判定専用台帳と隠し段の最大打ち返し

開始点714c6b2。同ブランチで実装・検収する。採用候補は全条件合格までE22。
`production_config.py`は変更しない。事前登録は `logs/e27/PREREGISTRATION.md`。

## 変更の境界

E26検収組合せに既定OFFの `--death-pending-ledger` と `--hidden-row-death` を追加した。
既存の `--pending-ledger` は今回使用しない。
前者は、単発着弾と複数着弾の死亡証明に渡す純受け量だけを交換独立台帳へ切り替える。
確率計算の `incoming`、S3特徴量、仮想着弾のG_fe、応手確率計算は従来入力のまま。
監査出力には別属性 `death_incoming` として記録し、死亡証明による確率固定は従来どおり行う。
独立台帳の残量変更は死亡保持の再評価条件に含める。

後者は、途中盤面の隠し段UNKNOWNが1〜3個の場合だけ、確認した試合4色＋空の全組合せを列挙する。
現在層のSTABLE確定盤面・履歴は変更しない。E26の途中完走予測はUNKNOWNを引き続き拒否する。
試合4色はその時点までのSTABLE確定セルを側ごとに累積した頻度上位4色から取得し、4色未確認・4位同点は拒否する。
落ち切りはE26同様に、GRAVITY_SETTLE中の二つの異なる時刻で同盤面が連続観測された場合だけ。
可視UNKNOWN、支持のないセル、4個以上の隠し段UNKNOWNは補完しない。

## 最大火力と死亡証明

各候補の残り連鎖は、元の絶対段数の連鎖ボーナスで得点を計算する。
次段の式読取と段数・累積点が一致した候補のみを有効化し、後続式と矛盾した候補も除く。
候補は専用オブジェクトに保持し、連鎖レコードの `predicted_final_*` へ書き込まない。
最大打ち返し候補の得点を台帳の複製へ適用し、相殺・既着地を履歴から再計算する。
この操作は元台帳も変更しない。最大火力が同点の完走盤面は全て死亡が証明できる必要がある。
生存枝、探索上限、不確実な盤面が一つでもあれば死亡断定を拒否する。
既存の複数着弾探索と同じ枝数上限と楽観的応手評価を維持した。

`HIDDEN_COUNTS.json` は列挙候補数・シミュレーション組合せ数・次段一致採用・死亡証明探索への使用を分ける。
`HIDDEN_USAGE.json` は純受け量をゼロへ抑えた場合も含め、死亡入力へ反映した交換数と再評価回数を数える。
`NEW_DEATH_CASES.json` はE22比の新規／前倒しを死亡観測信号へ照合する。
`VERIFICATION.json` は本番設定・モデル・元入力の不変と、E26との確率入力隔離を記録する。
新しい特徴量列を追加していないため、side反転・正規化のスキーマ変更はない。
