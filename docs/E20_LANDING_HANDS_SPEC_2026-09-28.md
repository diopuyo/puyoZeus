# E20: ゲーム仕様に基づく着弾前手数と確定的応手の再評価

基準候補は E15 live count + ②窒息後の発火拒否 + E19死亡確定表示（`ba614f7`）。
モデルは `models/exchange_event_v3`、入力は従来と同じ `logs/e16/records/`。
`production_config.py`、モデル、学習特徴列、対称化・正規化は変更しない。
新しい `--landing-hands-spec` は既定OFF。確率版応手は使用しない。

## 仕様と旧実装との差

ユーザー指定のゲーム仕様を判断基準とする。攻撃側NEXTの動き始めで攻撃が確定し、
受け側の現在の手が設置され、その手で連鎖しなければおじゃまが降る。
受け側が連鎖すればその終了まで延期し、相殺で予告が消えれば降らない。
予告への追加分は即降る。したがって固定の「連鎖数→着弾秒数」は使わない。

- 旧 `src/exchange_event_landing.py:41` は、連鎖数別の古い時間表から経過秒と受け側の
  推定操作不能秒を引き、固定 `SEC_PER_HAND=0.733` で割って最後の1手を足す。
  同`:251`付近の `_hands` は既存の終了合図・終了確認にも依存していた。
- 旧時間表は `src/indicators_v2.py:1396`付近に記された盤面settle実測であり、
  今回必要な「発火からNEXTが動くまで」の実測とは終点が異なる。
- 新経路は攻撃確定済みなら1手、進行中なら
  `1 + floor(max(0, 残りアニメ秒) / 受け側の直近設置間隔の中央値)`。
  受け側の固定秒数も、自側連鎖時間の別途控除も使わない。
- アニメ時間は過去に完了した同連鎖数の「発火→NEXT繰り上がり」の直近5件中央値。
  設置間隔は当該側のSTABLE確定盤面の2色ぷよ増加から得る直近5間隔中央値。
  5は観測窓の実装定数で、ゲーム時間の仮定ではない。未来時刻・勝敗は使わない。
  試合境界で設置履歴はリセットし、過去の完了演出実測だけは継続利用する。
- 生の `next_slide_motion` 単独は発光を拾うため、NEXT2→NEXT1の色の繰り上がりを
  2観測連続で確認し、開始信号の時刻を記録する。同色NEXT等では既存判定器が
  確認済みの `next` / `tsumo` 終了を補助に使う。検出・確認遅延は残る。
- 観測不足時は理由を明記して1手の下限に退避する。下限だけで回避不能死を断定しない。
  元の時間表への無言のフォールバックはしない。
- NFの `k` は元々 **既知NEXT2手を除く追加手数**。
  `src/exchange_event_landing.py:63` の `k=hands-2`、
  `src/indicators_v2.py:2955` の総探索手数`2+k`は整合している。
  1手ならk=-1、2手ならk=0。新経路の手数を応手・回避探索へそのまま渡す。
  学習済みモデルのcount特徴（`src/exchange_event_count_features.py:111`）や
  レビューパネルの固定k一覧は変更しない。E20は着弾予測層の手数差分を評価する。

## 8撃ち合いの実測を再点検

E19 `CLASSIFICATION.json` の「正→誤・着弾前の新発火なし」8件を固定した。
旧手数と新手数は、その撃ち合いで最初に応手を選択した**同一判断時刻**で比較する。
2976.917秒は表示代表時刻で、対応する予測判断時刻は2974.15秒。

重要な訂正: E19の `observed_time_budget_hands` は
`floor((fall_start_sec - decision_sec)/0.733)+1` の時間換算値であり、実設置数ではない。
さらに `fall_start_sec` は認識器のOJAMA_FALL遷移で、原映像では攻撃エフェクトだけを
拾ったケースがある。これを着弾真値にして「8件すべて過大」とは断定できない。

`logs/e20/VISUAL_HANDS.json` に原映像を見た設置区間・実落下区間・未着弾の区別を保存。
`frames/actual_game_*.jpg` は時刻付き根拠、`LANDING_OBSERVATIONS.json` は
盤面のおじゃま数の変化であり、後者単独を正解ラベルにはしていない。
応手で連鎖が起きた場面の実手数は、連鎖終了までの延期を含む事後観測。
未着弾の場面は「実着弾までの手数」を捏造せず欠測とし、応手・窒息までの手数を別記する。
