# 監査の部分再利用とCP継続（2026-10-08）

監査全体は消さない。比較器は `observe` の全項目を比較し、得点・桁・信頼度・式と、未採用のロゴやテロップ、`death_0/1` の生スコアも必要とする。`game/warning/boards/death` などはすでに認識結果から転記している。採用後の値で生の観測値を代用しない。

監査は完全に無副作用ではない。検出器の高速経路の計測カウンタ、PreparedTemplateのFFT・統計キャッシュ、ScoreOcrの遅延行列初期化が更新されうる。検出器とobserveの呼出しは残し、同一Runtime.step内の純粋な部分計算だけ再利用する。

`image_free_audit_reuse.py` は配列の全byte/dtype/shape/strideと引数を照合する。cv2の出力バッファ指定は対象外。認識側は実計算し、監査側でだけ既計算値を返す。戻り値を複製して呼出し側の変更を隔離し、次フレームへ値を持ち越さない。OCRは同じオブジェクト・ROI・設定の詳細出力に限定する。モデルとテンプレートは固定入力で実行中に交換しない。

検証票はリポジトリ外 `b3_data/codex_tasks/image_free_speed_audit_v2/proof.json`。既知の同居版c68 f11800–12159の旧新各360fと、f11980の連続前史CPからの旧新各180f、計1080経路fについて全項目・画素SHA・PTS不一致0。特徴行34/34/15/15。CP再開の2ケースでは、元の保存形式から新キャッシュ識別子への移行も実行した。旧キャッシュは新規領域で実計算した。

最初の候補は色変換まで管理して旧360fで1.739fpsに低下したため不採用。色変換を除いた候補の旧360fは1.993fps（既存1.907）、旧CP180fは1.842fps（既存2.099）。新360fは2.151fps（既存2.480）、新CP180fは2.310fps（既存2.163）。測定時の他負荷が異なり、速度向上は全ケースで確認できていない。旧だけ適用し、新の再利用は採用しない。本番の120秒以上の進捗差分を別途保存して見込みへ反映する。

旧360fの排他的内訳秒（復号/認識/会計/特徴/推論/監査/保存）は1.91/34.50/42.35/23.23/1.03/68.71/4.32。監査は既存75.15秒から68.71秒になったが、監査4割を丸ごと削減できたわけではない。初期化と旧キャッシュ内部保存などの残余は別。

`image_free_audit_checkpoint.py` は制御コードSHAもキャッシュキーへ含める。移行前CPの元コード・モデル・入力のfingerprintを既存restoreで厳密検査してから、同じ時系列状態を引き継ぐ。別のCPやキャッシュ読出し途中の状態は拒否する。元の全出力chunksを保持し、旧の新規キャッシュも先頭8f検算を続ける。コードSHA検査を無効化しない。

`image_free_audit_update.py` は合格票・SHAと対象監督の実コマンドを確認してから、その監督だけを停止・再起動する。新は現行監査のまま同じCPへ戻る。完了済み経路は再起動せず、空保存による末尾chunkの上書きを防ぐ。検証用の一時的な並列制限は期限付きで解除する。r2改版では新だけ別出力で0から、旧は継続する。未検証ソースには再利用を適用しない。

PC1は15:28 JSTに切替、旧d04 f15900、新c68 f12900/d01 f12300/d04 f11100のCPを保持。既定OFFの認識フラグ・分類器・モデルは変更していない。保険ジョブは触らず、pushしない。
