# G2収録資材の必要性確認

監査対象はPR #26の`603d9cb8a3823a85339bea8c993c68ae06d58d77`で追加されていた707ファイル。元のmain全体や未コミット成果物全体を対象にした監査ではない。

## 判定の意味

ここでの必要性は「A40診断の実行・固定ソース検査、修復前後の保存数学と回帰、検収説明を後から確認するための収録理由」である。「本番実行に707件全部が必要」「行単位で最小」「クリーンcheckoutだけで動画検証できる」という意味ではない。

判定はfile単位の[必要性台帳](G2_SOURCE_NECESSITY.json)へ、path・SHA256・分類・根拠を記録した。directory名が現れたという理由だけの未分類保持は終了し、707件を706保持・1除外へ判定した。新しい知識文書・本説明・台帳はこの監査結果を永続化するための追加資料で、元707件の分母には入れない。

独立Opusレビュー後、回帰入口・試験依存・後処理29件は名前規則だけで済ませず、親が目的・import先・実試験入口を確認し、ASTから入口名/行・import文/行・assert数を台帳へ採録した。除外1件も手動判断の根拠として、全収録py/shを明示列挙して参照を走査した。gitignoreで対象を落とすgrepは使わない。これらは任意の動的文字列生成や全分岐の非参照を数学的に証明するものではない。

## 確認方法と内訳

- 506件：実A40 creatorのCPU経路でmoduleのexecを観測したsource。最終型・binding・保存・参照解放の既存対照を再用し、156.55秒、例外なし。人工初期履歴で、動画更新やGPU推論の再走ではない。loadされたコードの全分岐が実行済みとは言わない。
- 139件：上記実loadとは重複させず、A40の`TARGET_GO.frozen_files`に含まれるsource。`target_entry.runtime_sources()`と`approved()`が要求する固定検査・終了/保存等の構成を保持する。
- 10件：A40 freezerが直接照合するA39固定source。旧freezerを再帰実行するからではなく、原ファイルのSHA照合に使うから保持する。
- 9件：原2P保存数学の`g2_second_pending_prefix_2026-09-14_v3/postrun.py`から参照されるA33固定検査セット。
- 10件：`g2_a38_postrun_2026-09-14_v1/review_arrivals.py`や旧M1回帰から参照されるA38の保存検証セット。現A40の本番依存と区別する。
- 25件：既知反例、修復後の正常/負例、実creator、人工終端保存の回帰入口。将来の破壊を検出するため残す。
- 1件：`terminal_ownership.py`。`test_first_terminal_candidate.py`がimportする試験依存であり、汎用退役機構を本番採用したものではない。
- 3件：A40の保存数学・終了票・完全性を確認した追加後処理。
- 3件：修復根拠、契約試験説明、承認済みストレージ方針。
- 1件を除外：`g2_second_terminal_arrival_2026-09-14_v2/session_selection.py`。v3へ置換済みで、実A40 load、維持する固定集合、現収録sourceの明示逆参照に該当しない。ローカル原本は保持する。

## 旧コードを残す理由と、残さない理由

旧v33には現行保存数学からの実importがある。旧v38は旧M1保存回帰と原保存検査に使う。古い日付でも、この接続を削れば検証経路が失われる。一方、前コミットで除外したv35〜v37の実行セットには、そのような現行実行・回帰からの直接接続がなく、古い固定票の再発行は対象外とした。

回帰と歴史資料を無制限に保存する方針ではない。今回残すのは、収録された検査入口が直接要求する実装・固定集合である。将来この依存を解体するときは、旧反例と保存数学を独立fixtureへ移してから原入口を削る。必要性の確認を、依存コードの設計が最良だという評価と混同しない。

## 依然として保証していないこと

- 私有動画、巨大原票、モデル、凍結認識snapshot、各runの承認票・XMLは別途必要。ソース収録だけで全統合テストや元runを再現できるわけではない。
- 回帰入口25件は、対応する私有fixtureを揃えて原手順どおり個別プロセスで使う。bare import/sys.pathと同名moduleがあり、repo全体のpytest一括収集では版衝突の危険がある。全CIへの自動組込みは未対応。持ち運び可能として今回確認するのは`test_portable_arrival_contract.py`の単独実行だけである。
- A40の元entry1、ROWS破損、未生成票、旧M1未評価は変更していない。
- sourceの必須性確認は、勝率精度・較正・複数動画一般化・全保存監査の合格ではない。
- 完全な動的分岐網羅や数学的な最小集合証明ではない。明示した診断/回帰構成を保つための保持判断である。

元checkoutと通常indexを保持し、PR専用indexで除外と文書追加だけを行った。その後のユーザー明示承認により、[G2限定マージの受入](G2_MERGE_ACCEPTANCE.md)に従ってPR #26を統合する。G3実走・本番採用は行わない。
