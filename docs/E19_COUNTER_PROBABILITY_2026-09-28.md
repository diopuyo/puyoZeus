## 2. 応手確率の実験

採否は q log loss ≤ .5313、zenchi ≥ 80.10%、誤発火 ≤ 1/28、
2612〜2614.08秒の62行平均 > .270 かつ前半31行平均 < 後半31行平均。
死亡表示修正とは独立に、E15+②へ `--landing-counter-prob` だけを追加する。

### 学習母数とラベルの限界

148動画すべてのティアを確認し、記録再生の評価動画IDとの非重複を検査。
32,055発火機会から、未発火の受け側で予測応手量 ≥ 受け量となる8,138候補を抽出した。
原票には実着弾通知がないため、連続したSTABLE観測でのおじゃま個数増加を着弾区間の代理にした。
区間の前に発火した781件を正例、区間末尾まで発火しない2,060件を負例とした。
着弾の帰属不明3,691件・未観測1,470件・区間内発火136件の計5,297件は除外した。
応手ありは「着弾前の新発火」であり、予測NF量を実現した、受け量を全相殺した、というラベルではない。

**識別可能2,841件中781件（27.49%）は、全8,138候補の実応手率ではない。**
完全相殺・観測間に消えた着弾を復元できず、識別可能標本への選択偏りがある。
また、原票に会計スナップショットがないため、受け量は相手の発火前盤面の完走予測送り量で近似した。
これは実着弾時刻・実会計を持つ全母集団ラベルによる学習の代替実験である。
推論時は既存の相殺済み受け量を使用する。この学習・推論の差も採否結果と分けて保持する。

### 合成

`G_fe = p(counter) × G_fe(応手あり) + (1−p(counter)) × G_fe(応手なし)`。
この予測層の合成後に、既存どおり S3 と logit 平均する。現在層の確定盤面は変更しない。
応手量が受け量未満なら確率0。両仮定のG_fe、確率、特徴、適用外理由、合成G_feをDTOへ保存し、
レビューCSVにも両G_fe・確率・合成G_fe・適用外理由を残す。モデルは差し替え可能な軽量JSON。

## 3. 死亡確定後の表示

原因は `src/exchange_event_layers.py:38` の `before()` が死亡を記憶して更新を拒否する一方、
`src/exchange_event_overlay.py:95` の早期returnが、最後の予測値 .764 を置換しないこと。
`--confirmed-death-hold` で既存の死亡ラッチと episode の片側死亡方向判定を再用し、
片側死亡が確定したら勝者確率1/敗者確率0へ切り替える。両側死亡なら片側勝利を断定しない。
既存の決着ホールドと同様にEMAを通さず表示し、EMA内部へ確定値を混入させない。
試合境界で既存ラッチと確率がリセットされる。①や③を有効にする変更はない。

2698.983333〜2701.216667秒の68表示行がすべて1P=1.000、有利不利=+100。
次の試合境界は2701.25秒。指定終盤2699.5〜2701秒の45行も最小1.000。
