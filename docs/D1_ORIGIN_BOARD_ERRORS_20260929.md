# D1 保存起点盤面の誤りの診断（2026-09-29）

## 結論と到達点

**221発火の棚卸し・可視差分の全数列挙は完了。元記録の全セルの書き込み経路特定は未完了。**
画像窓が成立した149発火で335セルの差分を検出し、特定できた最後の1組の41セルを除いた残差は294セル。
残差には最後の1組をまだ特定できない発火も含むため、294を「最後の1組以外の誤りの確定数」とは扱わない。
72発火は保存スナップショット自体が不成立であり、差分ゼロではなく計数不能。

zenchi 2P・連鎖ID9の4セルは、**赤緑の操作中の位置を先に保存し、移動後の位置と次の赤赤の着地を取り込めていない**。
最後の黄黄の読み間違いでも、この4セルを連鎖シミュレーションが消した直接の事例でもない。
再生計装では着地推論・UNKNOWNの空補完・浮きぷよ削除が組み合わさって同じ4セルの誤りを再現した。
ただし元の確定盤面全体とは一致しないため、再生の経路名をそのまま元記録の経路と断定しない。

3動画の13件の起点差分棄却には、W48と整合する連鎖後盤面の先取り、W47系の試合外画像、連鎖途中の通知、通常の盤面差分が混在する。
**一律に4セル制限を広げる根拠にはならない。**

## 3. 根治案（実装なし）

1. **W48系**：連鎖後予測をSTABLE確定盤面・起点履歴へ入れない。収集側のW48bと同じ保持条件を描画側の履歴保存にも適用し、連鎖終了の観測後にだけ更新する。
   `--enable-chain-active-record-hold` は `COLLECT_ONLY_ADOPTED` にあるが、描画の `recognition_load_default_kwargs()` は `RECOGNITION_ADOPTED` しか展開しない。今回の実引数にもholdは無く、`ExchangeEventOverlay._remember` はSTABLEを条件に履歴へ追加する。
2. **W47系**：発火・起点保存・画像窓に同じ試合範囲ゲートを通す。キャラ選択・勝利演出中はCNN=HSVでも盤面の根拠にしない。
3. **対象の着地取りこぼし**：接地・観測差分とロック確定を分け、操作中の位置から確定盤面へ書かない。上端の片側欠測を空で確定せず、ロック後の可視CNN=HSV一致と組の移動を照合して更新する。
4. **連鎖途中通知**：新規発火と途中段の再通知を識別し、途中の画像窓を発火前盤面として起点に照合しない。
