## ★★ アーキテクチャ決定 (2026-08-16、user) ★★
> 「構造+静止画が現実的な解。**打ち合いは当然構造で見るしかない、撃ち合っていない盤面は
> 静止画で形による判断をするしかない**」

### 2モード明示分離
| モード | 評価方法 | 根拠 |
|---|---|---|
| **打ち合い中** | **構造** = 物理会計 + 時間予算 (T秒→K手) + 火力見積もり (ビームサーチ) の再帰合成 | 未来が確定/半確定。形を見ても意味がない |
| **打ち合っていない** | **静止画** = 形の評価 (CNN本命 + 補助指標) | 何が起きるか未定。形の潜在力を評価するしかない |

### この分離が説明すること
- **指摘13/14/19 は全て「打ち合い中に静止画の判断を使った」or「境界の場当たり処理」**だった。
  今は1モデルで全部を見ており境界が暗黙 → 同型のバグが3回再発した。明示分離すれば境界は設計事項になる
- **終盤AUC 0.83 / 序盤AUC 0.50** と整合: 終盤は構造 (おじゃま差・連鎖差) が支配的で読める。
  序盤が読めないのは**静止画評価 (形) が未熟**ということ → 切り分けができる

### 必要な部品
1. **モード判定器**: 「今は打ち合い中か」。既存の決着ホールド機構 (発火検知・両者連鎖中判定) が原型
2. **構造評価器**: 物理会計 + 時間→手数 + 火力見積もり (ビームサーチ、8/12 user必須決定) の再帰。**認識精度に全依存**
3. **静止評価器**: 形の評価。**CNN が本命** (「End-to-end CNN base + 補助indicator」の既定路線と一致)
4. **受け渡し規約**: モード切替時に表示が飛ばないようにする (過去の「1秒で4段変化」はここの問題)

### 優先順位との整合
構造評価器も静止評価器も**認識した盤面が入力**。よって**認識の品質強化が先**という現在の方針と完全に整合する。

### モード境界の確定 (2026-08-16、user対話で詰めた)
| 状態 | 評価方法 |
|---|---|
| **量が未確定** (連鎖進行中、結果がまだ決まっていない) | **構造** (物理会計+時間予算+火力見積もりの再帰) |
| **量が確定〜ツモ着地〜おじゃま落下** | **着弾後盤面をシミュレートして静止画評価** + **1手の即発火チェック** |
| **着弾後** | **静止画評価** (復帰可能性) |

**userの整理**: 「おじゃまが確定してからはツモを置いた後おじゃま落下しての盤面のシミュレーション
になるので静止画に近い」→ **構造が要るのは量が確定するまでの間だけ**。落下中はもう打ち合いではない。

**ただし1手だけ構造が残る**: 確定後でも受け側がツモを置いたその手で発火すれば相殺できる
(おじゃまは連鎖完了後に降るルール)。**指摘19の場面がまさにこれ** (1Pが確定後の1手で大連鎖を発火して勝利)。
→ **「いま置ける手で相殺できる発火があるか」を1手分だけ調べれば済む**。深い読みも
当てにならないMC応手確率 (W15: 25〜40%止まり) も不要。**安くて確実**。

**重要な帰結**: W12は特徴量の問題というより「**どの盤面を見て判断するか**」の問題だった。
着弾前の綺麗な盤面で静止画判断をするのが誤りで、着弾後の盤面を評価すればよい。

### 復帰可能性 (着弾後の静止画評価) の方針
- **手作りのルールを書かない**。「掘れるか/色は残っているか/窒息余裕/形が壊れていないか」が
  絡み合い、人間も言語化できていない判断。過去に「催促条件」「形の品質」を手で指標化して3連敗した記録あり
- → **CNN が本命** (既定路線と一致)。ただし**学習ラベルを「最終勝敗」から「復帰できたか」に変える**
  (観測可能: 一定時間内に撃ち返せた / 耐えたが劣勢 / 窒息した の3段階程度)
- **投資前に信号量を実測する**: 「N個受けた後の復帰率」を単純な観測量 (おじゃま量・埋まった色ぷよ数・
  窒息余裕・色の連結残存) で層別。説明しきれない残りが大きければCNN投資の根拠になる
- **微妙な判定は微妙と表示する**: 理論チャネル (物理的に回避不能か) と実践チャネル (統計的な復帰率) が
  **割れる場面こそが微妙な局面**であり、割れていること自体が情報。単一の数字に潰さない

### 復帰判定の設計 (2026-08-16 user対話で到達した結論)

**結論: 「復帰したか」を判定しない設計にする。** 区切りもラベルも不要。

#### 到達までの経緯
- 当初案「復帰を3段階ラベルにする」→ user例で破綻: 「3段受けても相手の本線が遠ければ、
  2連鎖→相手発火→単発で掃除→本線で返し切る、という**複数ラウンドにまたがる展開**がある」
  → 着弾1回では切り取れない
- 次案「打ち合いシーケンス単位で見る」→ **user: 一区切りは難しい**。実戦では切れ目が曖昧
- → **user提案: 本線までの遠さ・相手の状況・双方の火力で類似局面を検索し、実績勝率を出す**
  → **これなら区切りが不要**。各時点で連続的に勝率が動くだけ。ラベル定義も不要

#### 決定的な利点
1. **区切り・ラベルを宣言しなくてよい** (試合境界検知すら苦労している現状で、打ち合いの区切り判定は脆い)
2. **微妙な局面が正直に出る** (似た局面が五分に割れていれば答えは本当に五分)
3. **根拠を見せられる** = 「この局面は○○ vs ○○のこの場面に似ています」。
   CNNと違い**人間が検証できる**。配信オーバーレイとしても強い
4. **既にuser決定済みの「理論値/実践値の二重チャネル」の実践側そのもの**
   (理論=物理会計で回避不能死、実践=類似局面の実績勝率。**割れる場面こそ本当に難しい局面**)

#### 局面を表す軸 (候補)
自分の本線までの遠さ / 相手の本線までの遠さ / 双方の火力 / おじゃま状況 / 窒息余裕。
**「遠さ」「火力」が中核で、これはビームサーチの火力見積もり器が要る = 認識精度に依存**。

#### 安く検証できる
既存データ (100万行) で近傍探索を試し、現行モデル (AUC 0.65) より当たるかを比較するだけ。
凝った実装の前に筋の良し悪しが分かる。

#### userの体感 (錨として使う、定数化はしない)
> 「体感だと**勝率38%以上になれば良い**とは感じる」

- **定数として組み込まない** (指摘12で確立した扱い: 所見は数字合わせに使わず、妥当性確認の錨とする)
- 使い方: データから「N段受けた後の実勝率分布」を出し、**38%あたりに意味のある境目が見えるか**を確認。
  一致すれば強い裏付け、ズレれば**なぜズレるかが次の論点**
- 注意: 「表示される勝率」でなく**実勝率**で測ること (現行モデルの校正は完全でない)
- **副産物の知見**: 体感が50%でなく38%ということは、大きく受けた後は
  **「五分に戻る」でなく「試合に戻れる」ことが成功**という非対称性がある。表示設計にも効く
