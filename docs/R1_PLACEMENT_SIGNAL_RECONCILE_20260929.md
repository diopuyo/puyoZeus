## 既存処理との関係

- `DriftDetector` は融合読取りとの連続乖離でstate machine全体をリセットする。R1はリセットせず独立一致セルだけを照合する。
- `infer_placement` は組の配置推論、`_merge_diff_only` は通常の状態遷移時の反映。R1はこれらの即時確定を変更しない。
- D3の `next_translation` と `multiply` の検出式・定数を `placement_signal_images.py` へ移植した。
- `AnimationFilter`、`is_effect_glow_active`、全消しラッチ、既存連鎖状態を品質棄却に流用する。
- CNNは既存モデルのeval推論を共有する。`classify_batch` / `predict_proba_batch` は推論値を返すだけで認識履歴を更新しないことを確認。HSVと画像品質の履歴はR1専用インスタンスに分離する。
- `PrefireSnapshotReader` の `grounded` を可視段へ適用する。`_apply_gravity_filter` は浮遊セルを削除するため、R1の判定には使わない。
- `_set_deferred_confirmed` を流用し、確定盤面・保留盤面・前STABLE値を同期する。修正セルだけ古い着地投票・色監視・長期CNN履歴から外し、graceも同期する。任意のPiecePersistence/Glow保護を併用している場合は、保護状態の修正セルだけを同期し、隠し段・無変更セルの履歴を残す（今回の本番認識設定では両保護ともOFF）。
- 60fps→30fpsの通常認識を維持し、ONだけ間引き前の原画像を照合へ供給する。画像番号が飛んだ場合は連続一致とみなさない。
- E34cの `functools.wraps` と元コマンド保存方式を利用する。E34の起点保持フラグは追加しない。
- OFFはE31の画像窓列の保存対象も維持する。ONは新しい盤面で発火対象となる連鎖を旧発火一覧で欠測にしないよう、観測された全開始通知の過去画像窓を保存する。既存の `capture_window` を使い、認識や旧収集時の評価器へは戻さない。
