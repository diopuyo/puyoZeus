## 決定済み (user 10/7)
- 表示はオプションで決める: 配置・デザイン (テーマ)・マスコットの有無ほか。
- マスコットは **user が用意する** (独自キャラ)。ゲームのキャラ絵は使わない。
- 配布サイトは **Cloudflare Pages** (無料)。
- 配布の形は **インストーラーと zip の両方**。
- サイトと表示の言語は **日本語＋英語**。

## 1. 表示のオプション
| 項目 | 選択肢 | 既定 |
|---|---|---|
| 配置 | 中央カード / リボン / 最小 / データ / L字 (四隅) | 中央カード |
| テーマ | classic / neon / arena / pop / noir | classic |
| 50% の示し方 | 上下塗り分け / 細線＋50 / 光帯 / 勝率線の色分け | 勝率線の色分け |
| 出す項目 | 勝率・直近推移・試合全体推移・状態・判定の中身 (各オンオフ) | 勝率・直近推移・状態 |
| 文字の大きさ | 小・中・大 | 中 |
| L字のゲーム縮小率 | 70〜85% | 80% |
| マスコット | なし / あり (位置: 左下・右下・カード横、大きさ) | なし |
| マスコットの反応 | 勝率で表情を切り替え (有利・五分・不利・決着の勝ち/負け)、大きく動いた時の動き | 反応あり |
| 表示言語 | 日本語 / English | OS の言語 |

決め方: 設定ページ (`/settings`) で見ながら選ぶ → 設定ファイルに保存。OBS の URL 引数で一時上書き。

### マスコット画像の受け入れ仕様 (user が用意するもの)
- PNG (背景透過)、各 512×512 程度以上。
- 表情 5 種: 通常 (五分)・有利・不利・勝ち・負け (足りない分は通常で代用)。
- 任意: 動き用の連番 PNG または APNG/WebP アニメ。
- 左右どちら向きか (1P 側・2P 側で反転するか)。

## 2. インストーラーの初期設定 (初回に聞く項目の案)

4. 表示の初期プリセット (配置・テーマ) — 見本画像から選ぶ。
5. マスコット (なし / あり)。

インストール後の初回起動で色の較正 (ウォームアップ) を自動で行う。

## 3. 配布サイト (Cloudflare Pages)
### ページ構成
- トップ: 何ができるか (動く見本)・ダウンロード (インストーラー / zip、版、更新日、ファイルの SHA256)・動作環境。
- はじめかた: インストール → OBS の設定 (仮想カメラを「ソース」出力、ブラウザソースの追加) → 試合を映す。手順は OBS の画面の図で。
- 表示のカスタマイズ: テーマ・配置・マスコットの見本、設定ページの使い方。
- よくある質問 / 困ったとき: 「接続待ち」「試合待ちのまま」「表示が遅い」「入力が見つからない」など。
- 更新履歴、ライセンス (MIT)、免責。
- 言語切り替え (日本語 / English)。

### 配布物の置き場所
Cloudflare Pages は 1 ファイル 25MB までなので、配布物 (圧縮で数百 MB) は別に置く。【要決定】
- 案A: GitHub Releases (無料・1 ファイル 2GB まで・版の管理が楽) — 推奨。
- 案B: Cloudflare R2 (無料枠 10GB、ダウンロード転送量は無料)。

## 4. 注意点 (要確認)
- **非公式であることの明記**: 「ぷよぷよ」は SEGA の商標。サイト・配布物に「非公式のファン制作ツール」と明記し、公式ロゴは使わない。
- **ゲーム画面の画像**: サイトの見本にゲーム画面を使うかどうか。【要決定】(使わない場合は、ぼかしたゲーム画面や図で代用)
- **署名なしのインストーラー**: Windows の SmartScreen が「不明な発行元」と警告する。コード署名証明書は有料 (年数万円)。当面は署名なしで、サイトに対処の説明を載せる案。【要決定】
- 配布物のサイズ: 展開後 約0.8GB (同梱の Python・ライブラリが大半)。軽くする余地は後で検討。

## 5. アーリーアクセス版の障害ログ (user 10/7: インストール時・実行時の障害ログを解析できる形で、Discord で集める)
### 仕組み (案)
- **決定 (user 10/7)**: 配布物 → **中継 (Cloudflare Workers、無料枠 1日10万回)** → ログ本体は **Cloudflare D1 (無料のデータベース) に構造化して保存**し、配布サイトに管理者向けの集計ページ (認証つき) を置く。**Discord には短い通知だけ** (新しい種類のエラーが初めて出た・同じエラーが急に増えた・日次のまとめ)。
  - Discord の Webhook の URL を配布物に直接入れると、誰でもそのチャンネルに書き込めてしまう (荒らし・なりすまし)。URL は中継にだけ置き、中継で回数制限・大きさ制限・形式の検査をする。
- 送る契機: インストールの失敗 / 起動の失敗 / 実行中の異常終了 / 「入力なし」「試合待ち」が長く続く等の自己診断の異常 / 利用者が「ログを送る」ボタンを押した時。
- 送る中身 (解析できる形 = 構造化 JSON ＋要約1行):
  - 版 (アプリ・モデル・コードの SHA)、OS・CPU・GPU・メモリ、設定 (ポート・入力の種類・オプション)、エラーの種類と発生箇所 (スタックトレース)、直前のログ N 行、インストールのログ、自己診断の結果 (入力の解像度・fps・較正の結果・処理の遅れ)。
  - 同じ原因をまとめるための「エラーの指紋」(種類＋発生箇所のハッシュ) と、匿名のインストール ID (個人を特定しない乱数)。
- **送らないもの**: ユーザー名・PC 名・フォルダのパスのユーザー名部分 (伏せ字に置換)、映像・画像 (既定では送らない。利用者が明示した時だけ、縮小したスクリーンショット1枚を添付できる)。
- 送る前の同意: 【要決定】(案: インストール時に「障害ログを自動で送る」を選ぶ (既定オン、アーリーアクセスの条件として説明)、送る内容はいつでも設定で確認・停止できる)。
- 送れない時 (オフライン等) は手元に保存し、次の起動時に送る。手元のログは `logs/` に一定量だけ残す。
### 解析
- Discord のチャンネルに届いたログを、統括 (Claude) が読み取り (Discord のボット or 書き出し) → エラーの指紋ごとに件数・版・環境を集計 → 修正の優先順位を付ける。
- 版ごとの「起動成功率」「異常終了率」を出せるよう、起動成功時にも最小限の通知 (版と匿名 ID だけ) を送るかは【要決定】。

## 6. user 決定 (10/7 続き)
- サイトの見本に**ゲーム画面は使わない**。図で代わりにし、**アイコンキャラクター (マスコット) を多用**する。
- インストーラーは**署名なし** (他に良い手が無ければ)。SmartScreen の警告の対処をサイトに載せる。
- 障害ログは**すべて手動**: 自動送信はしない。利用者が「ログを送る」を押した時だけ送る (インストール失敗・起動失敗・異常終了の画面に「ログを送る」ボタンを出す)。送る前に中身を見せる。
- 起動成功の通知は**送らない**。
- 配布物の置き場所は **Cloudflare R2** (user 決定 10/7)。サイトと同じドメインから直接ダウンロード、版の一覧はサイトの更新履歴で管理。リポジトリの公開・非公開に左右されない。

## 7. 署名と配布の形 (user 決定 10/7 夕)
- 0.6.0-preview.10 の試験で、署名なしのアンインストーラー (unins000.exe) が Windows のスマート アプリ コントロール (PC1 で有効、VerifiedAndReputablePolicyState=1) に止められた (CodeIntegrity 3077 / winerror 4551)。署名なしの exe は、この機能が有効な PC では動かない可能性が高い。
- 一方、zip 版 (中の python.exe は配布元の署名つき、同梱の puyo_core.pyd) は同じ PC1 で動いた (10/7 未明の OBS 試験、CodeIntegrity のブロック記録なし)。
- **決定: 署名は SignPath Foundation (オープンソース向けの無料のコード署名) を目指す。それまでは zip 版を主な配布にする** (インストーラーは「準備中」、または上級者向けの補足扱い)。
- SignPath の前提 (要準備): OSS ライセンス (MIT)、公開リポジトリ、GitHub 上での組み立て (CI)、履歴に残るゲーム画面の画像の消去 (既存の宿題)。
