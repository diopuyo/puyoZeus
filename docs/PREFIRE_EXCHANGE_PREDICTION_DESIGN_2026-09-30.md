## 0. 何を直すか

表示している勝率は、発火するまで動かない。受け側が打ち返せるかを発火前に織り込めない。
今の評価器は撃ち合いが起きた後の反応が速い (E1〜E36b)。起きる前の予測はしていない。
148動画 CV の T12 では、静止盤面の特徴から撃ち合いの結果はほぼ予測できなかった
(Spearman 0.096、符号 AUC 0.528)。残る道は探索型、というのが既存の結論である。
本設計はその探索型を、実時間で回せる大きさで作る。

## 3. 設計

### 3.1 出力

各時刻 t (両者 STABLE、確定盤面と NEXT/NEXT2 が揃う) に、「次の撃ち合いの帰結」の分布を出す:
`{branch: (重み, 撃ち合い後の仮想盤面ペア, 送り・受けのおじゃま, 帰結の勝率)}`。
混合して `p_prefire(t)` を作る。表示へは予測層 (C案) として入れ、画面と CSV に「発火前予測込み」と記録する。
現在層 (確定盤面の G_fe) は上書きしない。

### 3.2 二人対戦の軽量シミュレータ (`src/prefire_exchange_sim.py`、新規・状態なし)

1. **攻撃候補** (両側それぞれ): 既知2手を全列挙する (約3 ms)。その発火のうち得点上位 M 件を残す (M=4 を仮置きとし、学習で見直す)。
   加えて 3〜K 手目は MC で作る。4色等確率ではなく、その試合で確認した4色を使う
   (memory `reference_four_colors_per_match`)。1本ごとにビーム幅8・深さ4 を回す (約0.15 ms/本)。
2. **送り量**: `src/scoring.py` の `score_to_ojama`。マージンタイムの起点は両者のうち早い方
   (memory `reference_drop_bonus_and_margin_origin_2026-09-17`)。
3. **応手の猶予**: 攻撃側の連鎖時間 (連鎖数→秒の実測表) と、受け側の直近の設置間隔から手数を出す (E20 の仕様版を再利用)。
   降る条件は user 伝授の仕様どおりにする: 攻撃確定→受け側の現在の手が置かれる→連鎖しなければ降る。
   相殺で消えれば降らない。1回の着地は最大30個。
4. **応手**: 受け側は猶予手数内で、既知2手+MC により最大の相殺火力を得る。純受け量と余剰の返しを出す。
   再帰は深さ2まで (攻撃→応手→再応手)。深さは実測の応酬深さで見直す
   (応酬の96.8%は単発、memory `reference_saisoku_exchange_model`)。
5. **帰結の評価**: 仮想着弾した盤面ペアを既存 G_fe で評価する。窒息・回避不能死の判定は E35 の上限計算を流用する。
6. **枝の重み (発火するか待つか)**: ここは人の判断が要る (§5 Q1〜Q3)。初版は学習で決め、ルールを手で決めない。
   148動画から「t 時点の特徴 → Δ秒以内に発火するか」の hazard モデルを作る (LogReg/GBM、動画単位 CV)。
   特徴は探索が出す即時火力・相手の応手余地・高さなど。
   重み = P(攻撃側が Δ 以内に撃つ) × softmax(候補の得点)、残り = 「撃たない」枝 (現在層の値)。

### 3.3 評価器への混ぜ方

- `p_shown = σ((1−λ)·logit(p_current) + λ·logit(p_prefire))`。λ は発火の近さ (hazard) の関数とする。
  上限表では λ=0.5 でも利得の 83% が残るので、最初は控えめな λ でよい。
- 学習目標は、オラクルで使った「撃ち合い終了時点の表示勝率」を t 時点の特徴から当てる蒸留とする。
  加えて最終勝敗で較正する。どちらのラベルも、使う特徴は時刻 t 以前の観測だけ。
- 観測と矛盾したら予測層を捨てる (C案の既存規則)。たとえば予測した攻撃側でない側が先に撃った、予測と違う盤面が確定した、など。
  発火した瞬間からは、既存のイベント駆動評価 (S1′/S3′) に引き継ぐ。

### 3.4 実時間の計算予算 (1通知あたり償却 10 ms 以内、非同期可)

計算は確定盤面が変わったとき (設置ごと、片側 約1.4回/秒) だけ行う。NEXT が変わらなければ結果を使い回す。

| 部分 | 1回の見積もり | 回数 |
|---|---|---|
| 既知2手の全列挙 ×2側 | 5.6〜7.4 ms | 設置ごと |
| MC 応手 (幅8×深さ4) ×30本 ×上位4候補 ×2側 | 36〜70 ms | 設置ごと、別プロセスで非同期 |
| G_fe 評価 (仮想盤面) ×枝数 (~10) | 未測定 (B18c の保持 0.9〜1.3 ms を参考に 10〜20 ms) | 設置ごと、非同期 |

同期部分は約7 ms。非同期部分は 50〜90 ms で、rt の MC 応手 (30本非同期) と同じ仕組みで回す。
通知あたりに償却すると 10 ms 以内に収まる見込み (約3通知/秒)。
すべて単一プロセス・負荷あり条件の測定からの推定なので、範囲で示した。
実機では rt の B18 と同じ手順で測り直す。

### 3.5 リーク規則 (必須)

1. 特徴・分岐・目標値に使う盤面・得点・NEXT は、すべて時刻 t 以前に観測したもの。
   発火後の段観測・式・着地後盤面・撃ち合い終了時点の値は、学習ラベルとしてだけ使う。
2. 相手の NEXT は画面に表示されているので使ってよい (Q6 で user に確認)。未読の NEXT は番兵 `(9,9)` として除き、MC で補う。
3. 試合で確認した4色は、t までに見えた色だけを使う。
4. 監査: 打ち切り再生で確かめる。記録を t で切った再生の出力が、全長再生の出力の t までと一致すること (E32b と同じ方式)。
   各行の特徴の元盤面の時刻が t 以下であることも行ごとに保存する。
5. オラクル上限 (q .4769 @N=3s) より良い数字が出たら、採用前にリークを疑って監査する
   (memory `feedback_beats_oracle_means_leak`)。
