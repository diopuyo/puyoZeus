## 原因の切分け

`diagnose_live_v49f_numeric.py` は最初の 20 更新について、モデルへ入る特徴量の SHA・木の生出力・確率を記録する。Linux / Windows の **37 推論呼出し**で特徴量差 **0**、木の生出力差 **0**、確率差 **1**。不一致のロジットは両 OS とも `0.7885929774156966`。モデルの木や native 盤面処理より後の確率変換で差が生じている。`numeric_comparison.json` に原票を収録した。

補正値も、同一の保存済み `pre_records` と同一モデルから OS 別に再計算した。`advance_linux_2.json` / `advance_windows_2.json` は同じ特徴量・係数・ロジット `-0.848551824217765` から SciPy の expit が `0.2997367336553741` / `0.2997367336553742` を返すことを示す。math.exp による置換で枝の中間値は一致したが、最終補正値の差は残った（`advance_windows_scalar.json` / `advance_scalar_differences.json`）。単一の expit 呼出し置換では OS 間のビット一致を実現できなかった。

Windows の Python 3.12.3 / NumPy 2.4.4 / SciPy 1.17.1 / scikit-learn 1.8.0 を使用。少なくとも上記の再現差は、計算時間の打切りや CPU 負荷による入力の欠落ではなく、同一入力の確率変換の丸め差。すべての行の差がこの原因だけとは断定しない。原票を保持したまま数学関数の OS 間互換を検証し直す必要がある。
