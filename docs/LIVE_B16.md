# B16: S3再開時の欠測修正と評価障害の隔離

対象ブランチは `claude/realtime-phase-j-20260928`、基準は B15 `3a8874a`。
`src/production_config.py` は変更しない。

## 根因と保存記録による再現

B15の未完 `logs/live_b15/realtime/inputs.jsonl.gz` から、gzip末尾を要求せず
改行まで確定しているJSON行だけを別ファイルへ救出した。元記録は変更しない。
37,260通知中、最後の2試合の3,812通知（3744.750〜3878.017秒）を使用する。
抽出物は `logs/live_b16/recovered.jsonl.gz`、母数は `extraction.json`。

3877.417秒のS3が `p1=None, deferred=True` のまま、両側確定によって
`close_confirmed → DeferredTracker._close` を通り、計算待ち入力が破棄された。
連鎖継続の `ExchangeEventTracker._resume_existing` はこの交換区間を再開して
S3時刻・Noneの勝率を復元するが、計算待ち入力は復元しない。
S3時刻が存在するため `finish_frame` も再計算を予約せず、3878.017秒の
着弾評価がNoneとG_feをlogit合成して停止した。B7の公開直前計算に固有の経路。
元コードの保存再生は7.34秒で同じTypeErrorを再現した（モデル読込を除く）。

交換IDごとに最後の計算待ち入力を保持し、再開時に未計算なら復元する。
試合境界でこの保持をクリアする。着弾評価も未計算の基準値を合成せず保持する。
0.5等の代替確率は作らない。修正後の障害時点はS3_landingの実計算値へ進む。

`baseline_offline.json` と `fixed_offline.json` は3,812通知すべての勝率・評価種別が
完全一致、オフラインでは同じ例外は発生しない。ライブ修正後と子プロセス化後も
1スレッドの同条件で公開234回が完全一致する。集計は `verification.json`。
ライブ再生は6.79秒で全通知完走した。

## 隔離と復帰

ライブのイベント評価は `event-evaluation-worker` が所有する。親は認識・会計・
配信を継続し、入力通知を順番通り子へ渡す。モデル・状態機械・S3/着弾計算は
子に置き、監査表示には読み取り専用の現在値だけを戻す。
例外は `evaluation_errors.jsonl` に動画時刻、UTC、種類、スタック、PIDを記録する。
公開候補の組立を含むフレーム境界で捕捉し、数値なしのHOLD「評価エラー」を即時確定、
送信待ちの旧評価を失効させる。次の成功で通常表示へ復帰する。

失敗後は現在の試合境界以降の入力と成功済み計算を再生して状態を作り直す。
3回連続失敗、または子の異常終了では子プロセスそのものを交換し、PID変更を記録する。
連続失敗数は公開候補の組立まで成功した場合だけリセットする。
認識プロセスはこの再起動の対象外。再構築中のキューと捨ては通常の計測に含む。
入力journalは試合ごとに置換し、完了交換記録はディスクへ退避する。
子にも既存の上限付き連鎖キャッシュを適用し、RSSは子を含む所有プロセス合計で測る。

検証: `tests/test_live_b16.py` の単発故障、3連続故障、子強制終了、HOLD/復帰、
通知消費継続、同値・境界アーカイブ、未計算S3保持、公開完了の成功通知を含む。
新規12件を含む関連307件が成功。実動画の短時間接続は272通知、SSE24件、評価エラー0。
接続試験・pytestのログは `logs/live_b16/` に保存する。
