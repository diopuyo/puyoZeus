# Phase J B12: 外部負荷の識別とライブ縮退比較

基点 `9366e73`。同worktree・ブランチ。`src/production_config.py` は変更しない。

## 汚染計装

`scripts.measure_live_b12` が実行中のprocess groupを1秒周期で監視する。
`/proc/stat` のuser/nice/system/irq/softirq/stealからCPU時間差分を取り、
idle/iowaitを除外する。guestはuser/niceに含まれるため重複加算しない。
自group全PIDのutime+stimeを差し引いた外部CPU時間を、経過秒で割って
「使用コア数」として保存する。1.0は1論理CPUを全占有する時間に相当する。
PID再利用はstarttimeで区別する。終了processの最後の未回収時間は外部側に残る
保守的な計装であり、終了時の短いspikeをcleanとみなさない。

- `cpu_load.jsonl`: loadavg 1/5/15分、CPU tick差分、自group/外部/人工負荷/追加負荷、
  閾値、区間開始終了、valid、contaminatedを記録する。
- 外部CPUが1.0コア超の区間を汚染とする。人工負荷も外部に含める。
  比較時は所有したstress groupを別会計し、追加負荷の汚染印も並記する。
- 2.5秒を超えた監視間隔、会計不整合、記録範囲外はunknown。
  unknownを除外後の母数に入れない。
- `contamination.json`: 5分ごとに、汚染を含む/除く捨て数・対象frame数・率、
  SSE受信P95・母数、RSS中央値・母数を保存する。
- `unplanned_contamination.json`: 人工負荷を維持し、追加負荷だけ除いた同じ集計。
  これは無負荷成績ではない。
- SSE遅延はcaptureからsocket受信までの全区間で分類し、途中に汚染があれば除外する。
  置き対応は既存B8の全フレーム対照を使い、確定見落しと未解決を分ける。
  cleanの置き母数は対応探索範囲±2秒の全区間がcleanのものだけ。
- 母数は入力fps・開始frame・終端・strideから復元する。60fpsの奇数frameから
  30Hzへ正規化する場合、秒数×30の丸めでは件数と捨て位置がずれるため使わない。
  `metrics.json`の対象母数・捨て数と一致しなければ集計を失敗させる。

Linux/WSL内のCPU会計であり、Windowsホスト全体のCPU使用率を測るものではない。
Windowsの縮退制御は通知遅延を使う。Windows実機の性能値は今回の比較に含めない。

## 比較する制御

- a (`--cpu-isolation`): Linuxでは認識を許可CPU集合の先頭1CPUへ割り当て、
  評価・MCからそのCPUとSMT兄弟を除外する。外部アプリのaffinityは変更しない。
  Windowsでは認識をABOVE_NORMALクラスとする。REALTIMEクラスは使わない。
  従来の評価nice 10、ライブラリthread数1は全条件で同じ。
- b (`--adaptive-evaluation`): 外部負荷が1/2コア超、または通知遅延が100/250ms超なら、
  勝率計算の最短待機周期を0.5→1→2秒へ延ばす。5秒の回復確認後に1段ずつ戻す。
  認識通知・盤面確定・連鎖/着弾/得点・試合境界は全通知で更新する。
  オフライン再生には適用しない。
- c (`--event-priority`): 直前のツモ数変化、非STABLE、連鎖、着弾の
  兆候の後4slotだけ連続観測を優先し、latestより残す過去frameは最大2slot。
  終端後の古いtailは再生しない。未観測のイベントを予知するものではない。
  DirectShowでは取得専用threadが最大3枚のbufferを保持し、同じ選択方針を適用する。
  deviceの生成/read/releaseは取得threadが所有し、入力検証・較正は認識側に残す。
  overflowと選択時の捨て数を計上し、取得時刻・元解像度も維持する。
  実機カメラの性能は未測定。今回の比較値はWSLの動画入力である。

   採用比較には使用しない。外部約7コアを検出し、359対象frame全部に汚染印。
   除外後は母数0、率/P95はnull。`logs/live_b12/smoke/`。

   別々の物理core上の4論理CPU（0,2,4,6）内で、人工CPU占有3processをnice 0で動かす。
   測定も同じCPU集合内。人工負荷は計測前から終了後まで維持し、各case終了時に
   自分が所有するgroupだけを回収する。追加負荷の汚染も常時記録する。
   対照はB11の30Hz全対象frame再生 `logs/live_b11/baseline/`。
   試走の0,1,2,3は2物理coreのSMT兄弟を含んでいたため、採用比較では上記集合へ変更した。

再実行: `python -m scripts.measure_live_b12 --output logs/live_b12/comparison --wait-idle`
結果: 各caseの`comparison.json`、`contamination.json`、`unplanned_contamination.json`。
long: `python -m scripts.measure_live_b12 --long --selected <採用案> --commit <commit>`。
人工負荷なし・CPU集合の制限なしで、低負荷60秒（最長3時間待機）後に実行する。

**longはcのみ採用**。a/bは実装した切替を残すが既定OFFとする。
