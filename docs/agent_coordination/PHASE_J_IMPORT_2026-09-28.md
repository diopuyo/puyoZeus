## 未決仕様（このタスクでは判断しない）

### user判断が要るもの

- 実入力方式: ゲーム/ウィンドウ直接取得とOBSのclean source等のうち、配信環境で許容する経路・操作条件を確定する必要がある。
- GPU予算: OBS配信・認識・評価で許容するGPU/VRAM占有と配信品質への影響を確定する必要がある。
- P95/P99目標: 既存仕様のcapture→OBS表示P95 500ms/P99 1秒を最終採用するか、評価更新遅延を含む測定範囲とともに確定する必要がある。
- HOLD 2秒/決着1秒: 初期候補のままにせず、配信で許容する保持時間・決着表示時間の最終値を確定する必要がある。
- 仮想着弾合成と9/7 shadow契約: exchange側は仮想着弾M0/G_feとS3をlogit平均して表示確率を更新する一方、9/7契約はprojected入力を別層とし未採用M1勝率を更新しない。Phase J公開表示に適用する意味・採用条件の確定が必要。

### Claude判断で足りるもの

- 入力adapter比較の実装手順、フレーム時刻・欠落・再接続の計装方法、userが認めた経路内の試験設計。
- GPU予算内のworker数・スレッド数・キュー置換方針、低負荷になった後の本測定順序と計測窓。
- user確定の遅延/保持目標を各段の計測・タイマー・回帰テストへ割り当てる方法。
- shadow対象モデル（M1）とexchange表示経路の入力由来を別列で保持するDTO/監査設計。意味の衝突を実装修正だけで暗黙解消しない。
