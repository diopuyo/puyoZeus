# 全体計画 — 交換エピソード会計

更新: 2026-08-25 / 状態: Gate 3-2b 再レビュー HOLD、Gate 3R 是正中

## 目標

`催促対応 → 相手本線 → 自分本線 → 相殺 → 着弾` を一つの交換として追跡し、
進行中の暫定火力と確定会計を重複なく照合する。交換未解決中に根拠なく
99% / 1%を断定せず、交換確定後は正しい方向へ速やかに収束させる。

## Gate 0: 現在タスクを閉じる

- 掛け算式E2E、10ケース、偽イベント、8動画×3条件バックテストを完了する。
- PM100 pytestを完了する。負荷依存の速度テスト失敗は低負荷で単独再実行する。
- PM100全8区間結果と掛け算式結果をレビュー記録へ固定する。
- 完了前に関連ソースを編集しない。

## Gate 1: 観測仕様と不変条件

- 交換は最初の発火で開始し、相手の応射・再応射を同じ episode に参加させる。
- 各連鎖へ安定した `chain_id` を持たせ、formula再トリガーによる断片を統合する。
- イベントは発火・完走時刻順で処理し、OCR確定が遅れても順序を変えない。
- 暫定生成量は確定得点で「置換」する。確定時に再加算しない。
- 数学用pendingはcap前、表示用pendingだけ従来capを維持する。
- episode終了時に暫定残差、重複イベント、未照合量が0になること。

成果物: `docs/EXCHANGE_EPISODE_SPEC_2026-08-24.md`、代表場面のイベント表、
不変条件テスト一覧。

## Gate 2: 純粋な会計コア

- 新規 `ExchangeEvent` / `ExchangeEpisode` / `ExchangeLedger` を独立モジュールへ実装する。
- 中核は順序付きイベントを受けて符号付き純残量を再計算する純粋処理とする。
- provisional / finalized / reconciled / landed の状態を区別する。
- 既存APIは削除せず、optional引数または外部wrapperで接続する。
- 新フラグは既定OFF。既存OFF出力とのbit-identicalを固定する。

## Gate 3: 認識・表示への統合

- 掛け算式検知から安定 `chain_id` を供給する。
- `OjamaAccountingTracker` を確定会計の単一情報源とし、暫定イベントは確定時に照合する。
- `ResolvedExchangeTracker` の「両側同時chain_event必須」を、時間差応射も参加できる
  episode方式へ置き換える。ただし旧経路はフラグOFFで保持する。
- episode未解決中はkill overrideの完全上書き±100を禁止する。
- 実死亡、着弾確定、反撃不能が物理的に確定した場合だけ早期解除を許す。
- timeline dumpへ episode_id、chain_id、暫定/確定生成量、純残量、phase、
  hard-override保留理由を追加する。

## Gate 4: 検収

実行再現性の前提 (W39、2026-08-25):

- 同一コード・同一入力・同一フラグの独立3 runで、認識・会計キーだけでなく
  モデル特徴量、`adv_raw`、`adv_ema`を含む全決定キーがbit-identicalであること。
- 3 run一致しない評価値はGate 4の合否に使用しない。中央値・範囲は原因診断には
  使えるが、非決定性を残したままの合格根拠にはしない。
- W39決定化前のPM100値は履歴参照に限定し、全8区間を決定化後に取り直す。
- 効果量が小さい項目は同一窓3 runで再確認し、効果量が観測range外であることを
  追加条件とする。ただし上記bit-identical前提を代替しない。
- 画面品質の合否は、全表示frameを記録する密なdisplay timelineを母集団にする。
  settled更新時だけのtimeline dumpは認識・会計診断に限定し、張り付き率・急変・
  反転・決着方向の表示品質分母には使わない。決着ホールド中の表示は続いているため、
  settled行の欠落を表示の欠測とみなしてはならない。

2. 現行ヒステリシスBのみ。
