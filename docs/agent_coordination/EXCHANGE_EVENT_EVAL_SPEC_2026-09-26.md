# 撃ち合いイベント駆動評価 設計書 v1 (2026-09-26, Claude Opus 5.5 統括)

## 目的
中盤の勝敗は次の撃ち合いでほぼ決まり、撃ち合い前の状態からは読めない（148動画CV: 撃ち合い前 AUC≈0.58、撃ち合い結果の事前予測は不能）。
一方、**撃ち合いの発火時点**と**撃ち合い終了・着地前の得点差比較**で判定を更新すれば、着地後情報の上限（0.722）の約9割（0.708）が取れる。
本設計は、現行の「STABLE確定盤面での評価＋凍結」に、撃ち合いイベント時点の更新を加える。根拠: 56dc worktree の docs/agent_coordination/OPUS55_LEAD_PROGRESS_2026-09-26.md。

## 評価の3状態
| 状態 | 入力 | モデル |
|---|---|---|
| 静止 (両側確定盤面) | Dの46指標 + M0 logit + 充填量位相 + 経過秒位相 | G_fe（T09、条件付き候補） |
| 発火 (撃ち合いの最初の連鎖開始) | 静止入力 + 発火直前の両側確定盤面の特徴 + 近未来火力 + 発火側 | S1モデル |
| 撃ち合い終了・着地前 | S1入力 + 撃ち合い中の各側得点差÷換算レート（送り量）+ 相殺後純量 + 大小 + 得点欠測フラグ | S3モデル |
着地後に両側確定盤面が揃ったら静止状態へ戻る（着地後盤面で G_fe）。

## 不変条件
- 会計ledgerを特徴に使わない（既知の二重計上）。送り量は score OCR の差分から計算する。換算は src/scoring.py の既存関数（レート70、マージンタイム逓減）を使う。
- 撃ち合い終了は既存の絶対終了信号（連鎖側NEXTの移動／連鎖側へのおじゃま落下）に従う。得点が未確定なら S1 のまま待ち、確定したら S3 へ。
- 新フラグは既定OFF。採用登録（src/production_config.py）は検収とuser目視の後。
- 既存の決着ホールド・発火速報・片側STABLE更新との関係は、既存採用挙動を壊さない（新フラグONでのみ変わる）。
- モデルは差し替え可能な抽象（学習済み係数/モデルをファイルで読み込み）。RT向けに推論は軽量（GBMは木の数を制限、またはLRへ蒸留）。

## v1.1 改訂（既存資産精査 L1 を受けた統括裁定, 2026-09-26）
- R1 再用: 得点換算は `scoring.score_to_ojama`/`compute_effective_rate`、S3への遷移は `chain_id_resolver` の「終了合図→AWAITING_FINALIZE→SCORE_FINALIZE」を使う（参加した全連鎖が得点確定した時点でS3）。ledger closeとは分離。段別の `FormulaStepAccumulator` は将来のS2用に温存。
- R2 優先順位（新フラグONのとき）: **S3 ＞ S1 ＞ G_fe**。既存の発火速報（EarlyFireTracker の表示加算）と決着ホールド（完走シミュ仮想盤面のホールド）は新フラグON時は無効化し、二重計上と評価停止（最大45秒の評価行消失）を避ける。フラグOFFでは既存採用挙動のまま。
- R3 S3の0.708は「着地後行の得点＝着地前に観測可能」という仮定つきの値。実時間での得点確定時刻と着地時刻の前後関係をE3で必ず実測する（得点確定が着地より遅いケースの割合）。
- R4 E1の再現は2本立て: (a) T11と同一条件（D特徴＋発火特徴、固定÷70、3seed×5動画fold）で 0.638/0.708 を再現して実装の正しさを確認、(b) 本番用はマージンタイム補正換算で学習し、(a)との差を報告。
- R5 E3の検収母集団は全フレーム／イベント時刻で固定し、フラグON/OFFで同じ母集団を比べる（評価行が消えて張り付きが減ったように見える過去の錯覚を防ぐ）。
- 重複回避: ΔWinProb系（仮想盤面経由）・exchange_predictor の再実装はしない。train_exchange_stacking_rt は勝率が対象でないので流用しない。
