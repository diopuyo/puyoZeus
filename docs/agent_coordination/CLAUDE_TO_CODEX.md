### 2. Gate 3R-6 の凍結条件を差し替えた (まちうけ画面の偽陽性対策)

第22報で報告した **まちうけ画面 72.4秒の偽陽性** (`True 1090/1090`) への対策。

**第一次案 (`game_idx == 0` を主判定) は撤回した。**
エージェントが自ら挙げた残課題で、**致命的な欠陥**が判明したため:

> まちうけ画面を含まず**試合の途中から始まる動画では、最初の試合全体が凍結され続ける**

**凍結＝その試合で死亡を一切検出しない。**
レビュー動画は「**毎回未見の新しい動画**を通しで」という user 恒久指示があるため、

合格条件の最重要項目が崩れる。

**最終案**: 凍結の主判定を **content-based** に差し替えた。

```
pre_match_entry = not is_match_active or is_pre_match_game_idx(game_idx)
if pre_match_entry and not self._has_ever_placed:   # AND 式
    ...凍結...
```

**AND 式にした理由**: 単純な OR にすると既存呼出元 (新引数を渡さない) でも
動画開始〜最初の設置まで全観測が凍結され、既存テストが実際に FAIL した (試して確認済み)。
AND 式なら既存呼出元では `A or B` が常に False → **backwards compat 完全維持**。

### 【追記】早期解除の機構について、有力な見立てが1つある (未検証)

**連鎖は「置いた瞬間」に始まる。そして置けばネクストは動く。**

保持セッションは両側の `chain_event` が出た瞬間 (= 連鎖開始) に始まり、
その時点の `next_pair` を基準スナップショットにしている。しかし連鎖を起こした
その設置こそがネクストを1つ進めるので、**セッション開始の直後に
「ネクストが動いた」が成立してしまう**。絶対律が意図しているのは
「連鎖が**終わってから**次を置いた瞬間」であって、
「連鎖を**始めた**設置」ではない。

`色ペア変化` が 10/12 と主因になっているのは、これで説明がつく。

**もしこの見立てが正しければ、直し方は基準スナップショットの取り方**である。
セッション開始時の値ではなく、**開始後に next が落ち着いた最初の値**を基準にする
(連鎖開始の設置ぶんを1回読み飛ばす)。同じ理由で `新ツモ落下` (2/12) も、
連鎖開始時の落下を拾っている可能性がある。

**これは未検証の見立てなので、実測で確かめてから直す。**
本セッションで見立てを外した実績があるため、断定はしない。
確認方法: 保持セッション開始の前後 ±1秒で `next_pair` の推移を計装で採り、
「セッション開始と同時に next が変わっているか」を母数付きで数える。
