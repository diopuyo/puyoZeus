# 通し比較の履歴処理高速化（2026-10-08）

`image_free_speed_history_v1/` に変更前の計装、全出力照合、変更後の進捗を保存する。固定した認識本体・モデルを変更せず、独立した実行制御で `live_b3.reference_state` だけを置換する。画像なし認識の既定 OFF は維持する。

原因は `Runtime.evaluate` 内の表示用参照状態作成だった。`ExchangeEventTracker.records` は試合をまたいで増え、各レコードの `values` に評価履歴が蓄積する。従来の `asdict(record)` はこの履歴とその入れ子を毎フレーム深く複製していた。タイマー上は features に含まれる。

変更前の同じ c68 新経路CPで、11,800→40,200フレーム後に values は1,044→8,726件となり、参照状態作成5回の中央値は0.036845→0.511935秒（13.9倍）。40,200時点の追加プロファイル1回では1.660秒のうち asdict が1.659秒、総呼出し3,347,181回。d04旧34,200時点は values 9,379件、5回中央値0.829042秒。試合間でも履歴が残るため、動画経過とともに重くなる。

本番の同一PID内の差分では、c68新389f/305.50秒、d01新1,672f/1,351.08秒、d04新1,415f/1,347.41秒、d04旧1,248f/1,343.10秒。features はそれぞれ0.48255/0.52828/0.66915/0.70922秒毎フレーム、全時間の61.44/65.38/70.27/65.90%。母数は decoded frames。ネストした features の呼出し件数では割らない。詳細は `cause_receipt.json`。

高速版は `physical_times` が読む時刻だけを投影する。trigger/closed、chain の observed/end_signal、landing の fall_start/t の順序・型を維持し、元の `physical_times` / `np.unique` に渡す。current の重複追加も保持する。過去レコードの修正を見落とさないよう、可変履歴のメモ化や削除はしない。返す source/probability/physical は不変。

段3は早い c68 の旧・新各180f、および c68新40,200〜40,379と d04旧34,200〜34,379各180f。候補は全4ケースで90f後に保存して再読込する。全フレームの全項目・型・画素SHA・PTSを照合し、float は IEEE754 binary64 のビット一致を要求する。CPは認識本体のコード・モデル・動画SHAを照合して移行し、検証済み制御SHAだけを前版として認める。

長時間ケースの計算部分は c68新1.360→3.546、d04旧0.914→2.773経路f/s。features は各180fで77.805→0.314秒、127.502→0.463秒。これは保存・初期化待ちを含まない測定値。本番速度は更新後の同一PIDの進捗フレームと実時刻の差で別途測る。

CPU割当は起動の排他ロック、起動待ちargvの予約、tasksetによるPython起動前の固定を追加する。既存 affinity_guard による移動先の実マスクを優先し、監督の連続起動で同じCPUを選ばない。PuyoLive監督・両OS6GiB空き制限を維持する。

PC2は追加tar内の `image_free_history_preflight.py --root ...` でPC2自身の2万f以上の旧・新CPを読み取り専用で複製し、各180f（途中CP復元あり）を現行版と照合する。今回の制御SHAと結び付いた合格票がない限り更新を拒否する。合格後 `image_free_audit_update.py --root ... --start` で同じCPから再開する。前方補完・既存チャンクを維持し、B2と資源を分け合い比較を優先する。
