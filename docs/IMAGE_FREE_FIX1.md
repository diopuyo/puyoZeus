学習動画は B2 保存契約v2で保持した d03・d05・d06・d07。

教師は旧テンプレート経路。各動画2秒間隔に加え、死亡・終了ロゴ陽性の前後を採取する。
教師データはリポジトリ外へ32フレーム単位で確定保存する。
分類対象は死亡両側・試合終了・予告・連鎖数。連鎖数の座標は分類ラベルから分離する。
予告は旧教師と同じ色情報も必要なため、`refine_image_free_ojama` でBGR特徴を追加する。

予告のNoneはHSVへの棄却経路なので、希少クラス重みでNoneを抑制しない。
旧教師の予告テンプレートは6種類で、supercrownは資産がなく被覆対象にできない。
学習結果 `receipt.json` に標本数、種類別件数、陽性/陰性数、木の深さと使用特徴数を記録する。
陽性または陰性不足、単一特徴への依存、深さ1以下は被覆合格にしない。
既存の得点・全消し・中央テロップ等のモデルは今回の再学習対象外。

検証は以下の順序で行う。

1. 関連単体テスト。候補の `cv2.imread` / `PIL.Image.open` 禁止も維持する。
2. `scripts.verify_image_free_fix` で c68 の死亡・ロゴ・予告既知地点と
   d04 の確定チャンクから抽出した死亡張り付き開始地点の前後10フレームを比較する。
   旧教師・前候補・修正候補の離散値を保存する。この単体再生だけで品質合格にはしない。
   候補だけを変更した再試験では `reuse_stage2` によって旧教師・前候補の記録を再利用する。
3. 試合開始を含む2〜3試合の連続比較。`compare_image_free_all` の動画設定に
   `start_frame` / `end_frame`（終端を含まない）を指定する。
   原動画の絶対フレーム番号と時刻を保持し、処理数・観測試合IDを受領票に残す。
   表示勝率に残る各場面の原因を確認し、今回の死亡・終了変更による誤確定や盤面喪失が残れば全区間へ進めない。
4. 段3合格後だけ新しい `image_free_fix1_full/` へ固定ソース・モデルを配置し、
   PC1は既存の単一監視器 `image_free_parallel.py` で最大4並列起動する。

連鎖数の下流確認: `ChainCountOcr` は今回のライブ勝率計算から参照されていない。
比較アダプターのプローブと独立の教師・真値検証スクリプトが読み手である。
`ui.chain_count` の差をライブ勝率差の原因として扱わない。
