## 3. 最新要求の候補と不採用理由

`live_latest_evaluation` は既定 OFF。明示ON時だけ既存 b3_async に接続する。
coalesce_features は途中の特徴更新を省くが、通知会計とイベント評価の全更新は残る。

認識通知そのものを捨てる方式は、差分codec・得点・発火・死亡履歴を変えるため採用しない。
時間打切りも途中結果による勝率変更を避けるため採用しない。

## 2. 序盤の余計な区切り

40区切り中29件が得点合計300未満。近傍入力記録がある34件すべてで、transport_ready=True、
repeated=False、検証連続失敗数3を記録している。切断や同一画像の繰返しではなく画面内容検証からのepoch更新。
ただし原記録は検証器内部の得点・線分判定を保存していないため、34件全件の内部原因は断定しない。

指定録画は166.5秒で、序盤区切りg37/g39の2か所を収録する。各前後3秒、0.25秒間隔の計50枚を抽出した。
録画は配信オーバーレイ合成後なので、そのままでは50/50枚が自己画面検知に該当する。
検証器の自己画面検知だけをテスト台で無効化し、盤面・得点判定を分解した（製品コードは変更しない）。
分離後26/50枚が不合格。6枚は得点OCR不成立、20枚は得点を読めるのにgrid不検出かつ外枠照合不成立。
g39の録画60.21/61.21/62.21秒などで1秒周期3連続の外枠不合格が再現する。
序盤の空に近い盤面では内部grid線が得られず、アニメーション等で外枠Hough線分が不足する経路が主な再現原因。
録画時刻と入力時刻の厳密同期、OBS入力への色変換は未再現なので、当該実検証3枚と完全同一とは断定しない。

案: 一度検証済みの同一機器・同一サイズに限り、両側得点と盤面位置の継続根拠がある場合に外枠単独失敗を保留する。
効果見込みは序盤の誤棄却減少。悪影響はゲーム外画面への切替検知遅延・誤受理の増加。
入口判定、機器変更、得点不成立、自己画面検知は緩めず、負例動画で許容時間と再確認条件を検証する必要がある。
原因調査のみで製品の検証器・閾値は変更しない。原票: boundary_probe.json / boundaries_0.jpg / probe_boundaries.py。
