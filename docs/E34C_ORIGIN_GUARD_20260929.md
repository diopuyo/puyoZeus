## 修正と固定条件

E34bの合否は取消。[D2](D2_RECOLLECT_DIVERGENCE_20260929.md)で特定した
`configured(**kwargs)` の署名欠落を `functools.wraps(load)` で修正した。
実際の描画側既定値解決を通す回帰テストで、本番採用値と全実効引数を照合する。
保持印2個をONにし、試合範囲を原票ヘッダーへ保存した。
`src/production_config.py` は変更していない。

収集は旧E8/E10c/E14のコマンド・モデル・評価設定を維持し、
E16の終局観測、E26の連鎖中盤面、E31の発火前画像窓を原映像から再取得する。
補助観測は記録直前の複製へ付け、収集時の評価器には戻さない。
E8/E10cにはない `before_board` 列は追加せず、E14由来のreviewでは保存する。
旧原票から読むのは保存契約と照合値だけで、新しい観測値の補完には使わない。

各記録の先頭300認識行が出た時点で、確定盤面・状態・得点・NEXT/DNEXTを同期照合し、
不一致なら全収集へ停止通知を出す。全区間では保持印以外の認識入力列を照合する。
表示入力も全列照合し、静止特徴は再生器が参照するキー別D特徴を照合する。
`static_call` と `static` のM0・経過秒などは収集時評価器の履歴であり、
再生器は参照しない。原票内のこれらの履歴差も `checks/*.payload.json` に残す。
再生OFFについては旧E32の全表示列・イベント・診断をバイト単位で別途検証する。

認識入力は114,146/114,146行、表示入力は112,346/112,346行一致。
各記録の最初の300行も全列一致した。共通する静止Dキャッシュは6,699/6,699件一致。
zenchiの旧記録にだけある94キーは、OFF再生で使用した3キーの再計算値も旧値と一致し、
残り91キーは未使用だった。全5記録のOFF表示・イベントは旧E32とバイト一致、診断も一致した。
この検証をON開始前の必須条件とし、旧基準値を差し替えていない。
ONでも旧記録のみの19キーを再計算して旧値と一致し、残り75キーは未使用だった。

得点の採点行は `logs/e33b/cohort` を複製して固定し、ONの結果から母数を選び直さない。
旧E32のq・zenchi・誤発火と、E33bに保存された旧E32の得点誤差が再現されることを必須にする。
事前登録は `logs/e34c/PREREGISTRATION.md`、入力は `logs/e34c/records/`。

## 再現

WSLで以下を順に実行する。各段階は最大3並列、nice 10、setsid detach。

```bash
setsid -f bash scripts/_launch_e34c.sh
nice -n 10 /usr/bin/python3 -B -m scripts.compare_e34c_records
setsid -f bash scripts/_launch_e34c.sh --phase evaluate
```
