収集プロセスは起動のたびに `src/` と `scripts/collect_boards_lean.py` を読み込む。
**走行中にこれらを変更すると、148本の中で認識構成が混ざり、学習データが
汚染される**。148本が全て終わるまで、以下は変更しないこと。

- `src/` 配下 (特に `production_config.py`、`recognition_pipeline.py`、
  認識・状態機械まわり全般)
- `scripts/collect_boards_lean.py`
- `scripts/_regen148_orchestrator_2026-08-11.py` および本ジョブのスクリプト

変更しても収集は汚染しないが、収集完了前に走らせても意味がない。

## ダウンロード失敗分の回収 (走行中に発生する)

YouTube から 403 Forbidden が高頻度で返る。ほとんどはリトライ (最大4回、
間に8秒待機) で回復するが、4回とも失敗すると `collect_status=SKIP_DL_FAIL`
として記録され、その動画は欠測になる。

- 実測 (2026-08-18 07:20 時点): DL成功7本に対し恒久失敗1本 = 失敗率 12.5%。
  この率が続くと148本中18本前後が欠ける
- 原因は動画側の問題ではない。恒久失敗した 36 (c2ZJSOOA2qk) を個別に調べたところ
  DASH フォーマットは正常に存在しており、単に403が4回連続で当たっただけだった
- yt-dlp は 2026.07.04 と古いが、**更新はしない**。リトライでほぼ回復しており、
  走行中に動いているものを差し替えるリスクの方が高い

**回収方法**: パイプラインは再開可能で、`collect_status=OK` でない target は
次回実行時に再挑戦される。148本が一通り終わったら、**同じ起動コマンドを
もう一度叩くだけ**でよい。

```
wsl -d Ubuntu -- bash -c "cd /mnt/c/Users/ryouj/.gemini/antigravity/scratch/puyo_analyzer && setsid -f bash scripts/_run_regen148_recollect_2026-08-18.sh < /dev/null"
```

失敗率12.5%なら2巡目で残りは2本前後まで減る。3巡目でほぼ回収できる。
**全148本が `collect_status=OK` になったことを確認してから**、下の学習工程に
進むこと。欠測のまま学習に進むと、動画数が減った分だけ結果が前回と比較
できなくなる。

```

```

```
    --npz-dir data/indicators_v2/boards_lean_phase_l_2026-08-18 \
    --out-dir data/verify/phase_l_quality_gate_2026-08-18
```

**なぜ明示するか**: 前回のベースライン学習 (2026-08-14) は、入力になった
`boards_lean_phase_l_2026-08-11` に対して品質ゲートを走らせた形跡が無い
(ログを全文検索してもヒットしない)。品質ゲートを通した実績があるのは
2026-08-07 収集分だけで、そのときは148本中 FAIL=24 / WARN=26 / PASS=97 だった。
今回は8フラグ全群ONでこれがどう変わるかを比較材料にできる。
FAIL 動画の扱い (除外するか目視に回すか) は user 判断を仰ぐこと。

### 2. 学習CSVのビルド

```
python -m scripts.build_labeled_win_from_npz \
    --npz-dir data/indicators_v2/boards_lean_phase_l_2026-08-18 \
    --out data/verify/labeled_win_full148_2026-08-18/labeled_win_full148.csv \
    --profile full \
    --exclude-match-end-locked
```

- `--exclude-match-end-locked` は 2026-08-18 に標準採用として
  `src/production_config.py` の `LEARNING_DATA_BUILD_ADOPTED` に登録済み。
  ただし **既定 False で、付け忘れても何も警告されない**。収集側の
  `collect_flags()` に相当する呼び出しヘルパーが学習ビルダー側にはまだ無いため、
  手で付ける必要がある (事故防止の配線は今後の課題)
- 所要 **約4.4時間** (2026-08-14 実測15,939秒)。2026-08-13 の native 化で
  「23分に短縮」と見積もられていたが、その後に追加された列のコストで
  実測は4.4時間のまま。見積もりには実測値を使うこと
- `c26 / c30 / c58 / c69` の4本は `BROKEN_VIDEOS` として自動隔離され、
  144本が処理される
