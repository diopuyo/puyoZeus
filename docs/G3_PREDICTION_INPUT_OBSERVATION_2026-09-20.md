## 3. 窓が原因であることの確定 (段1、数秒)

(`data/verify/g2_history_baseline_adoption_2026-09-10_v4/witness.py:79`):

**純粋な区間判定で、他の条件は一切ない。**

差し替える対象が同じものであることも確認した

`sys.modules` 上の**唯一の実体**を同一性検証つきで返す。
`scripts/g3_native_scope.py` はこの同じオブジェクトの `FIRST_FRAME` だけを差し替える。

同ファイルにはこう書かれている:


**下限を広げないことは意図的だった。** `LAST_FRAME` は既に実走値へ拡張済みで、
**下限だけが G2 時代の値のまま取り残されていた。**

これは述語のコードと実測データから**演繹的に確定する**。

## 4. 未達: 実走での観測 (段3)

`END=9200` で s2 と同一区間・同一資源条件の s3 を組み、**起動した (2026-09-20 08:22)**。
前提24項目を読み取りだけで先に確認し、すべて OK だった。

**結果: exit_code 1。差し替えは発火せず (`replaced: 0`)。**
0件を成功と読み替えない仕掛けを入れておいたので、これは見逃されていない。

短区間の縮小自体は効いていた (`short_end: 9200`, `frames: 4600`)。
落ちたのは**予測入力とは無関係な場所**:

```
data/verify/g2_conditional_live_adapter_2026-09-10_v1/adapter.py:81
    assert all(cli.K.sha(Path(path)) == digest for path, digest in extra.items())
AssertionError
```

凍結された G2 アダプタ群が持つ SHA 照合。**複合条件のままなのでどれが偽かは残らない** ので、
分解して実測した (原則5):

- 計画の `entry_pins` **44 / 44 件は全件一致**。ここではない。
- 落ちているのは `candidate.guards()` 側の集合。
- **s2 の走行 (2026-09-16 14:34) 以降、`src/` と `scripts/` の .py が 48 件変わっている。**

### これは足場の漂流であり、予測入力の問題ではない

直すには凍結された G2 資産のピンを打ち直す必要がある。
これは **「Formal100・hidden reserve を開かない。SHA ピンは触らない」**
という制約に触れるため、独断で進めない。

**原則9「進まない投資は止める」に従い、ここで止めて user 判断を仰ぐ。**
