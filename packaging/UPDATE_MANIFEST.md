# 画面からの更新を出荷するときの確認

0.6.5 では `DISTRIBUTION_UPDATE_BUTTON=True` とし、画面からの更新を既定 ON にする。起動時の更新確認設定は既定 OFF のまま。

既存の配布サイトの `releases.json` と同じ取得先・User-Agent を使う。単体のオブジェクト、オブジェクトの配列、`releases` 配列を持つオブジェクトを受け付ける。`status` がある場合は `published` の版だけを選ぶ。

次は単体形式の例。SHAは実際のZIPから得た値を入れる。

```json
{
  "version": "0.6.5",
  "date": "2026-11-12",
  "summary": ["連鎖中の光への対処と中盤の推定勝率を改善", "配信停止とグラフ表示を修正", "画面から更新"],
  "files": [
    {
      "name": "puyoZeus-Live-0.6.5.zip",
      "url": "https://github.com/diopuyo/puyoZeus/releases/download/v0.6.5/puyoZeus-Live-0.6.5.zip",
      "sha256": "実際の64桁のSHA256"
    }
  ]
}
```

`url` がなければ上記のリポジトリ・タグ・ファイル名から組み立てる。`sha256` がなければ同じリリースの `SHA256SUMS` を読み、ZIP名と完全一致する1行を使う。SHAがない・複数ある・不一致なら入れ替えない。GitHubの別リポジトリ、HTTP、想定外ホストへのリダイレクトは拒否する。ローカルHTTPは試験台の明示的な注入だけで使い、利用者の設定や環境変数では有効にしない。

更新の作業フォルダは展開先と同じ親に作る。変更するファイルをすべて退避し、入替前に記録を同期保存する。設定・ログ・利用者のマスコットを保ち、外部のOBS設定や自動起動登録を直接書き換えない。別プロセスがアプリの終了を待ち、ファイルごとに原子的に置換する。新版のHTTP起動確認が取れてから完了にする。

起動前の復旧は `tools/launcher/update_recovery.py` が担う。旧版のPython本体が動くことを保つため、入口が読むDLL・標準ライブラリZIP・検索パスファイル・Python実行ファイルが異なる更新は入替前に中止し、ZIPの手動展開を案内する。0.6.4からの試験ZIPは同じPythonを使用する。将来Python本体を変更する版を出す際は、この制約を解除せず手動更新として案内するか、別途復旧方式を検証する。

成功・失敗時とも退避と作業記録は残す。`logs/update_result.json` に結果、作業フォルダの `transaction.json` に入替・復旧の記録を残す。復旧自体に失敗した場合は保留の記録も消さない。次回の通常の入口から再試行できる。

0.6.4には更新ボタンがないため、利用者の最初の0.6.5への更新はZIPの手動上書き展開。E2Eでは0.6.4実ZIPを展開した試験コピーに候補の更新経路を載せ、0.6.4の保存状態からの移行を検査する。
