puyoZeus Live セットアップ
================================================

2026-10-11 OBS試験版: 同梱の OBS_TEST_2026-10-11.md を上から順に進めてください。
puyo_live.json はB3用に設定済みです。下記の設定例から作り直す必要はありません。

1. 準備
   - このフォルダ (PuyoLive) を書き込み可能な場所 (例: D:\PuyoLive) に展開する。
     Program Files など書き込み制限のある場所には置かない (機器別の色較正を app\config に保存するため)。
   - puyo_live.example.json をコピーして puyo_live.json を作る。
     機器を選ぶのは device_index (0,1,2...) で、device_name は色較正の保存名 (名札) にすぎない。
     index が分からないときは、OBS の仮想カメラを開始した状態で
         PuyoLive.bat --list-devices
     を実行し、「映像あり 1920x1080」と出る index を device_index に書く。
     port を変える場合は OBS 側の URL も同じ番号にする。
     機器別の色較正の保存先は "calibration_location" で選ぶ:
         "app" (既定)   ... このフォルダの app\config\device_calibration
         "localappdata" ... %LOCALAPPDATA%\PuyoLive\device_calibration
     Program Files など書き込めない場所に置くときは "localappdata" にする。
     色の行列補正 "dshow_color_correction" (任意。項目が無ければ "off" = 何も変えない)。
     同梱の設定例は OBS 仮想カメラ + OBS 既定の色空間 (Rec.709) 向けに "601to709" にしてある。
     OBS の 設定→詳細設定→色空間 を Rec.601 に変えている場合は "off" にすること:
         "off" ... 補正なし (従来どおり)
         "601to709" ... OBS 仮想カメラを OBS 既定 (Rec.709) で使うとき、Windows が 601 で
                        復号してしまう色のずれを戻す。OBS 側を Rec.601 にしている場合は使わない
         "auto" ... 機器が YUV (NV12/YUY2 等) で映像を渡していれば 601to709 を適用

2. OBS 側
   - 起動順: OBS 起動 → 仮想カメラ開始 → PuyoLive 起動 → OBS のブラウザソースを再読み込み (または起動後に追加)。
   - OBS の 設定→映像→出力解像度 を 1920×1080 にする (720p での認識精度は未測定)。
   - ボードのキャプチャ映像を「ソース出力」で仮想カメラに流す
     (配信用の重ね表示を含めない。ぷよぷよeスポーツ画面のみ、1920x1080 / 16:9)。
   - 仮想カメラを開始する。
   - 次の手順で PuyoLive を起動した後、「ブラウザ」ソースを追加し、URL に http://127.0.0.1:8765/ を入れる (幅 1920 / 高さ 1080 を推奨)。
     既存のブラウザソースを使う場合も、PuyoLive 起動後に再読み込みする。

3. 起動
   - PuyoLive.bat をダブルクリックする。
   - 初回は「入力確認中」→「画面調整中 N%」の表示が出て、判定は較正が終わるまで出ない。
     「試合待ち」が続くときは入力番号の誤りも疑い、上記の --list-devices で device_index と映像を確認する。
   - 終了はコマンドウィンドウを閉じるか Ctrl+C。

表示の配置・内容を選ぶ
   - 起動後 http://127.0.0.1:8765/settings を普通のブラウザで開く (port変更時は読み替え)。
   - 手元のゲーム実フレーム画像を選ぶと、その静止画で配置を確認できる。画像は送信・保存されない。
   - 配置、四隅、縮小率70〜85%、文字サイズ、表示項目を選び「URLをコピー」。
   - OBSのブラウザソースは幅1920・高さ1080、位置(0,0)、最上面に置き、コピーしたURLを貼る。
   - L字型ではゲームキャプチャの「変換→変換の編集」で、位置と大きさを設定ページの値に合わせる。
     基準点は左上、クロップは0。80%なら1536×864。左上は(0,0)、右上は(384,0)、
     左下は(0,216)、右下は(384,216)。下寄せ時の横帯は上側に出る。
   - 仮想カメラはゲームのキャプチャだけの「ソース出力」を維持する。
     配信シーン全体を入力しない。縮小は配信シーンの変換だけで行い、認識入力1920×1080は維持する。
   - ゲーム部分は透明。横帯なしなら全体推移と判定の中身は側列に出る。
   - puyo_live.json の最上位の overlay が既定値。設定ページでJSON例をコピーし、他の項目を残して編集する。
     ファイルの変更は次回起動で反映。URLの引数はそのブラウザソースだけを上書きする。
   - 既定は L字 + 試験用パネル (デバッグ期間のみ。中央カードは /?layout=card&debug_panel=false)。L字の例: /?layout=l-right (ゲーム左上) /?layout=l-left (ゲーム右上)。
   - 試合全体の推移はページが受信した範囲のみ。途中から開いた場合、過去分は復元しない。
   - 現行B3が公開していない量や連鎖後予測は「未提供」と表示する。

4. うまくいかないとき
   - [設定エラー]     : puyo_live.json の書き方。メッセージの項目名を直す。
   - [配布物エラー]   : ファイルが欠けている/書き換わっている。展開し直す。
   - 画面に判定が出ない: OBS の仮想カメラが開始済みか、映像がぷよぷよeスポーツ画面 (1920x1080) か確認する。
   - ログと記録は output フォルダに出る。

動作に必要なもの: Windows 10/11 (64bit)。GPU は不要 (CPU のみで動作)。
Visual C++ ランタイム (vcruntime140 / msvcp140 等) は python フォルダに同梱済み。
不足の場合は起動時に [実行環境エラー] で案内が出る (公式: https://aka.ms/vs/17/release/vc_redist.x64.exe)。
