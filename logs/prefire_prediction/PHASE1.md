## 1. 価値の上限 (オラクル)

入力は本番構成の記録 `exev/logs/pending_expiry/e36b_on/on` の5本。再生はやり直していない。
採点のときだけ、発火の N 秒前から「撃ち合い終了時点の表示勝率」を注入した。
注入する区間は、同じ試合の中で直前の撃ち合いが終わった後に限る。
注入なしの採点が本番記録値と一致することを先に確かめた: q .5075670 (6,526行)、zenchi 7,671/8,333。

| 条件 | q LL | q AUC | q 発火前3秒 LL (573行) | q 発火前10秒 LL (1,413行) | zenchi 一致 |
|---|---:|---:|---:|---:|---:|
| 現行 | .5076 | .7752 | .7308 | .7342 | 7,671 |
| N=1 完全 / 半分 | .4953 / .4978 | .791 / .788 | .5915 / .6195 | .6778 / .6891 | 7,805 / 7,806 |
| N=3 完全 / 半分 | .4769 / .4821 | .814 / .807 | .3818 / .4407 | .5927 / .6166 | 7,918 / 7,919 |
| N=5 完全 / 半分 | .4658 / .4706 | .819 / .813 | .3818 / .4407 | .5412 / .5637 | 7,922 / 7,923 |
| N=10 完全 / 半分 | .4372 / .4417 | .834 / .834 | .3818 / .4407 | .4095 / .4300 | 7,922 / 7,923 |
| 対照 (目標値を入れ替え、N=3) | .7648 | .751 | 3.660 | 1.922 | 7,882 |

- 「半分」は logit 0.5 の混合。半分しか当たらない予測でも、q の改善の約83%が残る (N=3)。
- q の対照は大きく悪化する。したがって q は、発火前予測の測定器として健全である。
- **zenchi は感度が低い。** 対照でも +211 行上がる。終盤1/3にかかる発火前区間は13撃ち合いしかない。
  表示の adv と p1 の符号が 992 行で食い違う。zenchi は「悪化しないこと」の確認だけに使う。
- 参考 (認識由来のラベル、各1試合): fc は .3343 → .3206 (N=3)。mia は .7672 → .7929 に悪化した。
  mia は撃ち合い後の評価自体が勝者と逆を向いており、上限は撃ち合い後の評価器の正しさに縛られる。
- 現行では、発火前3秒の LL .731 が全体の .508 より大きく悪い。発火前は、今いちばん外している区間である。
  ただし4試合・573行なので、AUC .28 (発火前3秒) は参考値にとどまる。

## 4. user に聞きたいこと (ドメイン判断、推測で決めない)

1. **撃つか待つか**: 上級者は、撃てる連鎖があるとき何を見て撃ち、何を見て待ちますか。
   たとえば相手が着弾までに返せない量か、相手の発火点の高さ、自分の窒息余裕など。上位2〜3個を教えてください。
2. **本線が完成してから撃つまで**: 本線が撃てる形になってから、平均で何手くらい伸ばしてから撃ちますか。
   催促の場合はすぐ撃つ、という理解で合っていますか。
3. **小さい攻撃への判断**: 1段 (6個) 前後が来たとき、受ける・対応する・本線で打ち返すの選び方を教えてください。
   基準は、自分の盤面の埋まり具合や相手の残り火力でしょうか。
4. **応手のミス**: マスター級の打ち返しは「猶予手数内で最大の相殺をほぼ必ず組める」と見てよいですか。
   それとも実戦では届かない・組み損ねることがよくありますか。E19 では、打てると予測した側が実際は撃たない例が8件ありました。
5. **相手の NEXT**: 上級者は相手の NEXT/NEXT2 を見て撃つタイミングを決めていますか。予測に相手の NEXT を使ってよいですか。
6. **表示**: 「撃てば勝てるが、まだ撃っていない」状態は、勝率の本体を動かすべきですか。
   それとも本体は据え置き、予測込みの印と別の帯で見せるべきですか。

## 5. 判断

上限は十分にある。発火3秒前に撃ち合いの帰結が分かれば、q の LL は .5076 → .4769 (−.031) になる。
半分しか当たらなくても −.026 で、実用効果の下限 −.002 を大きく超える。
現行は、発火前の区間 (LL .731) をいちばん外している。
設計書 §3 の探索型シミュレータで Phase 2 に進む価値がある。
ただし、枝の重み (撃つか待つか) は user の回答 (Q1〜Q4) を受けてから決める。
